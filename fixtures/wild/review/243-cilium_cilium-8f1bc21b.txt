bpf: tests: consume plen/flags in mock_fib_lookup

The plen and flags parameters are not used by the mock itself, and
marking them __maybe_unused allows LLVM to dead-code-eliminate the
caller-side setup of R3/R4 at the fib_lookup() call site. The
argument registers are then left in an arbitrary state at the pseudo
call, and the verifier rejects the program with "R4 is not a scalar"
(btf_prepare_func_args) whenever unrelated code changes shift
register allocation.

Consume both arguments through volatile sinks so the caller-side
argument setup is always emitted.

This is a latent fragility since the mock was introduced (56b724d071,
deepened by 430dd4f376 which turned the 4th argument into a runtime
CONFIG() read); it surfaced in #49355 because its new CONFIG() reads
in the NAT path shift register allocation.
