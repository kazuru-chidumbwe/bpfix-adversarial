fix: ensure read buffer size is never negative

When compiling with clang versions > 20, the bpf_execve_event.h fails to
load with:
    R2 min value is negative, either use unsigned or 'var &= const'

as newer clang versions seem to generate the check for if (args_size) as
a check relative between to registers (i.e. if r1 == r3) rather than
explicitly comparing against 0 - which causes the wrong registers to be
bound checked.

So instead we just introduce an explicit check for the case in which
args is at most '\0', and bail early (with the good side-effect of
avoiding an unnecessary call to bpf_probe_read size a size of 0). Being
explicit keeps the verifier happy.

Signed-off-by: Rafael Roquetto <rroquett@isovalent.com>
