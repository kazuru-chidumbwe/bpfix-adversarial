bpf: write retprobe error before the map calls in copy_char_buf/iovec

In the has_return_copy() branch the only use of the args_off() pointer was
the final store, so clang computed the pointer after retprobe_map_get_key()
and retprobe_map_set(), keeping the offset on the stack across them. Kernels
before 5.5 lose the bounds of a stack-saved offset, so the verifier rejected
the access with:

  math between map_value pointer and register with unbounded min value is not allowed

This commits stores before the calls to keep the pointer arithmetic where the
offset is still bounded. The behavior should not change.

Signed-off-by: Daniel Gomez <dangome3@cisco.com>
