bpf: Pass snat_v6_needs_masquerade args by map

The next commit is going to make snat_v6_needs_masquerade a global
function. Unfortunately, we cannot pass objects by pointers if they are
then used for a map lookup because the verifier rejects it.

If we try that and use tuple->saddr to lookup the endpoint, the verifier
rejects our program with:

  3342: (79) r2 = *(u64 *)(r10 -80)     ; R2_w=mem(off=0,imm=0) R10=fp0
  3343: (85) call bpf_map_lookup_elem#1
  R2 type=mem expected=fp, pkt, pkt_meta, map_key, map_value
  processed 337 insns (limit 1000000) max_states_per_insn 0 total_states 14 peak_states 14 mark_read 5

In short, the verifier is expecting the second argument of that helper
to match ARG_PTR_TO_MAP_KEY but it's getting PTR_TO_MEM instead, which
doesn't match. We have PTR_TO_MEM here because we're using a global
function and that's the usual type when passing pointers to the stack
or map values.

Turns out that commit [1] upstream relaxed this constraint in v6.2 by
having PTR_TO_MEM match ARG_PTR_TO_MAP_KEY. Unfortunately, we still have
to support older kernels than that, so we'll need to workaround. An easy
workaround is to pass these arguments via a BPF array map. That also
saves a bit of stack space.

1 - https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=d1673304097c
