fix: Mask file type offset in the same asm block as the add

The existing mask is defeated by clang > 20: it spills the masked
value to the stack and reloads it before the access, and pre-5.7
verifiers lose the range across the spill, rejecting the load on 5.4
with:

  R9 unbounded memory access, make sure to bounds check any array
  access into a map

Fold the mask and the pointer add into one asm block so nothing can
be scheduled between them. The constant part of the offset stays a
displacement on the load, so it cannot wrap the mask: on v511 builds
args->len reaches 4095 and masking after the add would fold offset
4103 back to 7.

Signed-off-by: Tam Mach <tam.mach@cilium.io>
