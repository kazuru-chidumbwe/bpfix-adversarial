fix(driver/modern_bpf): avoid d_path on remote task paths

The synchronous task iterator reads path fields from tasks that can run
exit_mm() or exit_fs() in parallel. bpf_rcu_read_lock() satisfies the
verifier's trusted-pointer requirement, but it does not acquire references
to the remote file, fs_struct, dentries, or mounts. bpf_d_path() can
therefore enter d_path() with an object freed during task teardown and
trigger a general protection fault.

Use the approximate path helpers for executable, cwd, and root fields.
They traverse paths through no-fault BPF reads rather than passing
unpinned remote-task objects to bpf_d_path(), preventing the kernel oops
and its secondary Tasks Trace RCU warnings. Path output retains the
existing approximate-helper semantics.
