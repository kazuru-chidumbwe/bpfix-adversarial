.eh_frame: Reduce size of the stack aggregation key

Currently our BPF program fails to load in some kernel versions with the
following message:

```
level=debug name=parca-agent ts=2022-11-03T16:27:31.404098688Z caller=cpu.go:197 msg="increased max memory locked rlimit" limit="18 EB"
libbpf: Error in bpf_create_map_xattr(stack_counts):Argument list too long(-7). Retrying without BTF.
libbpf: map 'stack_counts': failed to create: Argument list too long(-7)
libbpf: failed to load object 'parca'
```

The "Argument list too long" means that `E2BIG` is returned. After
reading libbpf's code it seemed that this error could only be returned
by the kernel.

>        E2BIG  Argument list too long (POSIX.1-2001).

The max key size of BPF hash tables got bumped in this commit [1], which landed in v5.11-rc1~169^2~259^2~25 [2]
and bumped the number from 512 [3] bytes, which we very quickly
exhausted as 100 frames * 8 Bytes is already more than the threshold,
not accounting for the other data in the key or the map metadata!

- [1]: kernel change: https://github.com/torvalds/linux/commit/c6bde958a62b8ca5ee8d2c1fe429aec4ad54efad
- [2]: `git describe --contains c6bde958a62b8ca5ee8d2c1fe429aec4ad54efad`
- [3]: `MAX_BPF_STACK` https://github.com/torvalds/linux/blob/3d7cb6b0/include/linux/filter.h#L86

Which matches what we saw in our setups, as we run `5.10.57` in Minikube
and greater than that in our dev boxes.

(See test plan in the PR)

+// Avoid pulling in any other headers.
+typedef unsigned int uint32_t;
+
+// murmurhash2 from
+// https://github.com/aappleby/smhasher/blob/92cf3702fcfaadc84eb7bef59825a23e0cd84f56/src/MurmurHash2.cpp
+uint32_t MurmurHash2(const void *key, int len, uint32_t seed) {
+  /* 'm' and 'r' are mixing constants generated offline.
+     They're not really 'magic', they just happen to work well.  */
+
+  const uint32_t m = 0x5bd1e995;
+  const int r = 24;
+
+  /* Initialize the hash to a 'random' value */
+
+  uint32_t h = seed ^ len;
+
+  /* Mix 4 bytes at a time into the hash */
+
+  const unsigned char *data = (const unsigned char *)key;
+
+  while (len >= 4) {
+    uint32_t k = *(uint32_t *)data;
+
+    k *= m;
+    k ^= k >> r;
+    k *= m;
+
+    h *= m;
+    h ^= k;
+
+    data += 4;
+    len -= 4;
+  }
+
+  /* Handle the last few bytes of the input array  */
+
+  switch (len) {
+  case 3:
+    h ^= data[2] << 16;
+  case 2:
+    h ^= data[1] << 8;
+  case 1:
+    h ^= data[0];
+    h *= m;
+  };
+
+  /* Do a few final mixes of the hash to ensure the last few
+  // bytes are well-incorporated.  */
+
+  h ^= h >> 13;
+  h *= m;
+  h ^= h >> 15;
+
+  return h;
+}
