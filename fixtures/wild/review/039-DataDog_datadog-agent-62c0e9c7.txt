[USM] Support HTTP/2 path by value (#44188)

### What does this PR do?

This PR adds support for detecting and capturing HTTP/2 :path headers that are sent as literal keys (HPACK index=0) instead of using the static table references.

When HTTP/2 clients send custom paths (not / or /index.html), some implementations transmit the entire header (both key and value) as literals. Without this fix, USM would skip these headers entirely, missing important request paths.

The implementation detects literal :path headers by examining the first 2 bytes of the key name and remaps them to static table index 4, enabling proper path capture. It supports both:
  - Plain encoding: :p (bytes 0x3a, 0x70) with string length 5
  - Huffman encoding: bytes 0xb9, 0x58 with string length 4

Scope: This PR intentionally focuses only on :path detection (not :method or :status) to minimize eBPF instruction count and avoid verifier errors.

### Motivation

 Why only :path?
  - :path with literal keys is common in production traffic (~5-10% of requests) when clients use custom paths
  - :method as literal keys is extremely rare (<0.01%) - GET and POST are in the static table
  - :status as literal keys is virtually never seen (<0.001%) - common status codes are all in the static table

  By focusing on :path only, we:
  - ✅ Cover 95%+ of real-world literal key cases
  - ✅ Stay under the eBPF verifier instruction limit
  - ✅ Fix the CI failures


### Describe how you validated your changes

Added two test cases in `usm_http2_monitor_test.go`:
