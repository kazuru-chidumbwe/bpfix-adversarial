* feat: DNS-verified host filtering via connect-time verification

Replace SNI/Host header host resolution with a DNS-verified chain that
uses only kernel-controlled data:

1. DNS interception (recvfrom tracepoint) captures hostname→IP mappings,
   filtered to only watched hosts (from getkloak.io/hosts annotations)
2. Connect tracepoint cross-checks destination IP against dns_ip_map;
   stores verified fd in last_verified_fd[tgid] on match
3. SSL_write resolve_host uses last_verified_fd to walk the verified chain:
   fd → conn_ip_map → IP → dns_ip_map → hostname

Works for all languages (Python, Node.js, Go, Go-BoringSSL) since
connect() is a kernel syscall every app calls.

DNS parsing uses flat-loop + barrier_var pattern for BPF verifier safety.

* fix: BPF verifier bounds error in DNS answer parsing

Use __builtin_memcpy into stack buffer for the 10-byte RR header
(TYPE/CLASS/TTL/RDLENGTH) instead of per-byte pkt[m+N] accesses.
The verifier can't prove m+9 < 512 after dns_skip_name returns an
unbounded offset. Copying via memcpy with barrier_var + bitmask
ensures the access is provably in-bounds.

* fix: language-agnostic DNS interception via kprobe, BPF verifier fixes

Replace syscall-level DNS tracepoints (recvfrom/read/recvmsg) with a
single kprobe/kretprobe on udp_recvmsg. This captures DNS responses
for all languages regardless of which syscall they use:
- Python: recvfrom (worked before)
- Go: read on connected UDP socket (was missed)
- Node.js: sendto/recvmsg on unconnected UDP (was missed)

The kprobe filters on skc_dport==53 for connected sockets and allows
dport==0 for unconnected sockets (c-ares pattern), with tracked_tgids
and DNS response validation limiting scope.

Also fixes:
- BPF verifier bounds errors for RR header, A record, and AAAA record
  reads on second+ loop iteration (masked offset + N could exceed map)
- iov_iter read using __ubuf_iovec.iov_base for kernel 6.x ITER_UBUF
- Mount tracefs in Helm chart for tracepoint attachment
- Remove dns_config map and is_dns_server (no longer needed)

* fix: scan fds 3-10 in resolve_host when last_verified_fd is not set

When DNS is captured globally (by a Docker DNS proxy), the timing is:
1. App connects to server (conn_ip_map populated)
2. DNS response captured (dns_ip_map populated)
3. App writes TLS data (resolve_host called)

Step 2 happens after step 1, so tp_exit_connect doesn't find the IP in
dns_ip_map and never sets last_verified_fd. With persistent connections,
there's no second connect to fix this.

Fix: when last_verified_fd is not set, scan fds 3-10 in conn_ip_map
for any connection whose IP is DNS-verified. Cache the result in
last_verified_fd for future calls.
