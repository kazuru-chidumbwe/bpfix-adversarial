[BPF] Bump cali_v4_frags map version after in-place layout change

An unused struct bpf_timer was added to struct frags4_value, growing the
value of the cali_v4_frags and cali_v4_frgtmp maps from 1512 to 1528 bytes
without bumping their version suffix. On nodes that already had a pin from a
build with the previous layout, libbpf refuses to reuse the mismatched pin
("parameter mismatch", -EINVAL); because these are global maps shared by the
TC programs, the whole object fails to load for every endpoint and
BPFEndpointManager never goes ready, wedging calico-node at 0/1.

The timer field was never used (only frags4_fwd_value's timer is armed), so
remove it to restore the original layout, and bump both maps to version 3 so
the new program looks up a fresh name and sidesteps any incompatible pin left
behind by an earlier build.
