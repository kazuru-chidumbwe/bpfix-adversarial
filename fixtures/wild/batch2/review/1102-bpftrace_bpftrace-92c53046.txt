stdlib: Fixed strerror() and signal_name() failing BPF verification (#5145)

On fedora 44 amd64 llvm 22.1.4, `strerror()` and `signal_name()` cannot pass the
verifier's validation, `syscall_name()` works fine, for example strerror:

    tracepoint:syscalls:sys_exit_openat,
    tracepoint:syscalls:sys_exit_openat2
    {
        $errno = args.ret;
        @[strerror($errno)] = count();
        exit();
    }

Error: `errors[var_off=(0x0; 0x3fffffffc0)]` failed:

Using a mask to control the range of array access can solve this problem.

The max errno is EHWPOISON (1000 0101), then mask will be `0xff`.

I tried several methods, but I could never pass the verifier in both Fedora [1]
and Ubuntu [2][3] environments at the same time. Only this method using a mask
can support various kernel and LLVM versions simultaneously.

[1] Fedora 44 kernel 6.19.14-300.fc44.x86_64, llvm 22.1.4
[2] Ubuntu 24.04.4 kernel 6.17.0-1014-nvidia, llvm 18.1.3
[3] Ubuntu 26.04 kernel 7.0.0-15-generic, llvm 21.1.8
