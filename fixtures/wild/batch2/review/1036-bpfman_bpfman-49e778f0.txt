Assert the verifier rejection in the broken-sibling load test

The multi_prog_one_bad fixture put its unverifiable "bad" program in an
xdp.frags section, on the mistaken premise -- stated in a comment --
that two programs must sit in distinct sections to stay separate. They
need not: each SEC-annotated function is its own program, keyed by
function name, so "good" and "bad" are already distinct within a single
xdp section.

The frags section also meant "bad" failed to load before the verifier
ran, so the script's negative assertions only checked that the load
failed, never that the verifier was the cause -- the very thing the
fixture exists to demonstrate. A load that failed for any other reason
would have satisfied the test equally.

Move "bad" into the xdp section so it reaches the verifier, and assert
that the two failing loads name the packet-access rejection. Assert too
that selecting "good" alone loads exactly one program named "good", so
the positive case proves the broken sibling was skipped rather than
only that something loaded.
