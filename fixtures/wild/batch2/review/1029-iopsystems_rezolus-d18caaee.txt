feat(ext4): ext4_ops sampler: fsync, unlink, write and rename held time (#1349)

* feat(ext4): ext4_ops sampler: fsync, unlink, write and rename held time

Step 6 of docs/journal/2026-09-28-filesystem-telemetry-gaps.md (C5, C6).
How long each request-path call held its thread inside ext4, from the
calling side: ext4_op_latency{op} histograms; per-filesystem ext4_ops,
ext4_op_time, ext4_op_errors and ext4_write_bytes through the new
FilesystemCounters reader; per-cgroup cgroup_ext4_ops and
cgroup_ext4_op_time, the time a service's request threads are held by
the filesystem.

fsync and unlink come from their enter/exit tracepoints; write and
rename have none and are fentry/fexit on ext4_file_write_iter and
ext4_rename2, the latter with a program per arity (a namespace argument
was added in 5.12) selected from BTF by the new
kernel_btf_func_arg_count. kernel_btf_has_funcs now consults module BTF
too, since these functions live in ext4.ko on most x86_64 kernels. The
start timestamp is task local storage with one slot per operation, so
an O_SYNC write's inner fsync keeps the outer write's timing; task
storage and fentry on a module function are both 5.11, the floor the
sampler already had.

Off by default until its probe cost is benched: two probes per call on
the request path. The ext4 dashboard gains Operations (latency, calls,
mean latency and errors per mount) and Write Path (application,
writeback, journal and device bytes on one axis); the cgroup dashboards
gain ext4 Blocked Time. The slabinfo statics get a non-Linux dead-code
allow, since that file is included on every platform.

* fix(ext4_ops): 5.12 floor, queued async writes, opt-in list, unsupported status

Review findings:

- Task local storage reached tracing programs in 5.12, not 5.11, so the
  floor is 5.12 and the five-argument ext4_rename2 twin (pre-5.12 kernels)
  could never load; removed. The arity is still confirmed from BTF and the
  rename pair disabled on any count but six.
- An async direct write returns -EIOCBQUEUED from ext4_file_write_iter; it
  is no longer counted as an error, and the docs say its bytes are not in
  ext4_write_bytes and its latency is submission time.
- ext4_ops is in OPT_IN_SAMPLERS, so [defaults] enabled = true never turns
  it on; "off by default" now holds beyond the shipped agent.toml.
- A kernel whose BTF lacks the tracepoints reports Unsupported, not failed.
- Docs: a disabled operation's series read 0, not absent; stale
  kernel_btf_has_funcs paragraph and the "own types only" claim corrected;
  BPF_SAMPLERS gains the ext4 and writeback samplers; the redundant
  exact-name attribution entry dropped; the Write Path copy no longer
  assumes the application-bytes term.

* fix(bpf): probe task storage through the kprobe program type

libbpf refuses to probe helpers for BPF_PROG_TYPE_TRACING (-EOPNOTSUPP
before any syscall), so the previous probe reported every kernel
unsupported. kprobe programs draw helpers from the same table
(bpf_tracing_func_proto), which is where 5.12 added task storage for
tracing programs, so probing that type asks the same question. A test
asserts the probe is answered by the kernel rather than refused by
libbpf.

+// Close operation `op` on the current thread: latency into the op's
+// histogram, count and time into the filesystem's slot and the cgroup's.
+// `ret` is the call's return value (negative errno on failure; for a write,
+// the bytes written). An async direct write returns -EIOCBQUEUED: not an
+// error, and its bytes are not known here, so it counts as a call whose
+// latency is the submission time and adds nothing to write bytes.
+static __always_inline void op_end(u32 op, long ret) {
+    struct task_struct* task = bpf_get_current_task_btf();
+    struct op_start* s;
+    u64 start, lat;
+    u32 slot;
+
+    if (op >= OP_COUNT) {
+        return;
+    }
+
+    s = bpf_task_storage_get(&starts, task, 0, 0);
+    if (!s) {
+        return;
+    }
+
+    start = s->ts[op];
+    // possible we missed the start
+    if (!start) {
+        return;
+    }
+    s->ts[op] = 0;
+
+    lat = bpf_ktime_get_ns() - start;
+    slot = fs_slot(s->dev[op]);
+
+    switch (op) {
+    case OP_FSYNC:
+        histogram_incr(&fsync_latency, HISTOGRAM_POWER, lat);
+        break;
+    case OP_UNLINK:
+        histogram_incr(&unlink_latency, HISTOGRAM_POWER, lat);
+        break;
+    case OP_WRITE:
+        histogram_incr(&write_latency, HISTOGRAM_POWER, lat);
+        break;
+    case OP_RENAME:
+        histogram_incr(&rename_latency, HISTOGRAM_POWER, lat);
+        break;

+    counter_add(slot, C_TIME + op, lat);
+    if (ret < 0 && ret != -EIOCBQUEUED) {
+        counter_add(slot, C_ERRORS + op, 1);
+    }

+        counter_add(slot, C_WRITE_BYTES, (u64)ret);
+    }
+
+    cgroup_account(task, op, lat);
