fix: drop bpf_get_current_comm from cgroup_skb programs (#304)

The kernel does not expose bpf_get_current_comm to cgroup_skb programs, so the verifier rejects http3_egress/http3_ingress and the DNS query probe with "program of this type cannot use helper bpf_get_current_comm" (observed on a DigitalOcean kubernetes node). Leave the comm field zeroed; userspace already resolves the process name from the pid when ProcessName is empty.
