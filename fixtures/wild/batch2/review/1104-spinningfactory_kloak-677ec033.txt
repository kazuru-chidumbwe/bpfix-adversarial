fix(ebpf): load tc_ghash_update on Linux 7.2 (#354)

* fix(ebpf): load tc_ghash_update on Linux 7.2

Since Linux 7.2 the controller exits at startup, v0.2.0 and main alike:
the verifier rejects tc_ghash_update with "R4 unbounded memory access".
7.2 keeps a constant added to a pointer in its variable bounds instead of
a fixed offset, and a negative constant reads as an unsigned bound of
U64_MAX. gf128_mul_iter's shift loop (v[j] = v[j] >> 1 | v[j - 1] << 7,
j from 15 down) was compiled to a pointer that steps down from mul_v by
-1, -2, ..., so its second pass was rejected, though every byte it reads
is in the map value. 7.3-rc3 has the same check.

The step now lives in helpers.h as gf128_mul_step, with the loop fully
unrolled so every index is a constant. The XOR into z is masked rather
than a branch on the bit: with the branch, clang loads all of v ahead of
it and spills it, taking the callback's stack frame from 8 bytes to 144.
The reduction stays a branch; without one the callback has nowhere for
7.2's verifier to prune repeated visits, which cost it 60K more
instructions. gf128_mul and gf128_mul_ws use the same step, so the
userspace tests now cover what BPF runs, and a GCM test case 2 known
answer checks the reduction, which the algebraic tests could not.

* perf(ebpf): build the GHASH block delta without a branch per byte

On Linux 7.2 the verifier walked 361K instructions of tc_ghash_update
(2.6K on 6.8), 99% of them in ghash_block_iter's block delta loop: two
comparisons per byte against patch bounds it does not know, 16 bytes, so
the paths multiply and 7.2 no longer prunes them. BPF has no conditional
set, so any comparison is a branch.

ghash_block_delta (helpers.h) does the range check with arithmetic: d is
pos - sec_off in 64 bits, and the byte is in the patch when d's top bit
is clear and d - len's is set. The loop is unrolled so every out index is
a constant, and barrier_var keeps each byte's arithmetic in its own
iteration; without it clang computes all 16 up front and spills them,
taking the callback's frame from 32 bytes to 248. The memset goes, since
every byte is now written.

tc_ghash_update now costs the verifier 2,701 instructions on 7.2 and
1,786 on 6.8, with the same stack; it grows from 1,042 to 1,232
instructions. A helper test checks the new code against the old loop for
every patch length at every offset in the first 400 bytes, and at the
edges, including offsets where the old u32 sec_end wrapped.

* perf(ebpf): verify the SNI host copy once, not once per extension

On Linux 7.2 the verifier walked 859K instructions of
bpf_kprobe_tcp_sendmsg_sni (160K on 6.8), 86% of its 1M budget, and 86%
of that in tls_parse_sni's host copy loop. name_off indexes buf, so the
verifier tracks it precisely, and its range differs with the extension
that held server_name: each of those paths walked the 64-byte copy on
its own.

tls_parse_sni now stores name_off to *host_len and reads it back through
volatile before the copy, and the kprobe points host_len at the map
value (s->st.len) instead of the stack. The verifier does not track map
memory, so every path reaches the copy with the same unknown name_off,
which is only used masked. *host_len is reset to 0 straight after, so
the results are the same.

The program now costs 166K instructions on 7.2 and 168K on 6.8, with 16
bytes less stack.
