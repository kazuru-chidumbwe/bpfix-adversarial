bpf/analyze: sign-extend constants after dereferencing

Before comparing values to signed integer global consts smaller than 64 bits,
the compiler will emit lsh/rsh instructions on the loaded map value to make
sure it's properly sign-extended, since the value occupies fewer than 64 bits
in the data section.

This commit teaches the backtracker to tolerate these shifts and uses them as
a heuristic to perform its own sign extension, since it would incorrectly sign-
extend uints before, leading to hard-to-debug behaviour. This makes sure it sees
the same value the verifier would see, which would result in false negatives
(deleting used maps) otherwise.

Signed-off-by: Timo Beckers <timo@isovalent.com>
