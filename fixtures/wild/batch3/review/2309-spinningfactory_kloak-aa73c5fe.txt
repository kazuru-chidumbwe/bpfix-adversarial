feat: make virtual-ip the default host resolution, deprecate dns-snoop (#327) (#344)

--host-resolution and the chart's controller.ebpf.hostResolution now
default to virtual-ip. dns-snoop stays selectable for one more release,
deprecated: the flag help and values.yaml say so, and the controller
warns at startup.

Virtual-ip mode no longer depends on DNS snooping:

- Whether tc matches a record by its write sequence or by TLS record
  framing (memory_bio) was "resolve_host found no socket fd", and
  resolve_host also tries the DNS chain (last_verified_fd, the fd scan),
  so Go and Node were classified by whether their connection's address
  was seen in DNS. It is now decided by how the TLS library writes, in
  both modes: an SSL_write whose BIO holds no fd is a memory-BIO write
  (Node, Bun); Go crypto/tls writes each record to its socket within
  Write.
- In virtual-ip mode resolve_host only clears the host, IP and port
  (bpf_xor_path already ignored them there), and the udp_recvmsg kprobe
  and kretprobe are not attached.

The connect and close tracepoints stay in both modes: the SSL_write
uprobe uses conn_ip_map to skip server-side connections.

CI: the required "E2E Tests" leg is now virtual-ip (TCX, NRI,
dual-stack); the tc clsact, polling and Cilium legs follow the default,
and one "E2E Tests (dns-snoop)" leg remains. The README describes host
verification with virtual IPs and has an upgrade note; the trusted DNS
servers' help now says they are added to kube-dns's discovered addresses.
