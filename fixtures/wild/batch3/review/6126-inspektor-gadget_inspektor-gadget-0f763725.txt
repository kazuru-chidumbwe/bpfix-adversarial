profile_cuda: reduce BPF stack frame size for older kernels

Move struct gadget_user_stack and struct alloc_val from stack-local
variables to per-CPU array maps in gen_alloc_exit(). This reduces the
BPF stack frame by ~216 bytes (72B + 144B), bringing it well under the
256-byte limit.

The 256-byte limit is enforced by the BPF verifier on kernels < 6.13
when a function contains both BPF-to-BPF subprogram calls and tail
calls. Upcoming work on OTel eBPF Profiler symbolization (PR #4925) will
add a noinline function with bpf_tail_call() inside
gadget_get_user_stack(), which triggers this check. With the original
~248-byte stack frame, the verifier would reject the program on kernels
5.4 through 6.6.

Linux 6.13 introduces private stack support (PRIV_STACK_ADAPTIVE) for
kprobe programs, which allocates each subprogram's stack independently
and avoids the cumulative depth check entirely.
