dyninst: support compound conditions spanning entry and return events (#50205)

### What does this PR do?

Today, dyninst rejects when-clause expressions whose leaves resolve to variables from different event kinds. A method probe with both an entry and a return event must place every leaf in the same event — typically all in entry (parameters) or all in return (return values, locals, `@duration`). The restriction lived in `analyzeCondition` (irgen.go), which returned `IssueKindConditionVariableUnavailable` on any compound that mixed event kinds.

This change lifts that restriction so users can write `arg.size > 1024 && retval.err != nil` or `@duration > 100ms && retval.err != nil` on a single probe — the natural way to express "fire when an interesting input produced an interesting outcome."

### Approach: per-leaf 2-bit status with AST replay

Each entry-side leaf is compiled into its own SM sub-function (`ProcessConditionLeaf`). The entry-side condition handler becomes a driver that calls each leaf in turn and records its outcome — false, true, eval-error, or nil-deref — as a 2-bit status in a per-call `condition_state` (uint16, packed into `call_depths_entry_t` alongside `probe_id` and `entry_ktime_ns`).

A leaf-internal abort (nil deref / OOB / map miss) calls `sm_return` once, landing back in the driver rather than aborting the event handler. This isolation is what makes short-circuit semantics correct: the driver captures whichever leaves succeed and whichever errored, without one leaf's failure poisoning the others.

The entry-side gate and return-side condition both run as **AST replays** over `condition_state`. Each entry leaf in the AST lowers to `SM_OP_CONDITION_LEAF_LOAD`, which reads the 2-bit status:
- `LEAF_FALSE` / `LEAF_TRUE` → write the bit at `sm->offset`, continue.
- `LEAF_EVAL_ERROR` / `LEAF_NIL_DEREF` → set `condition_eval_error` (and `condition_nil_deref` for the latter), write 1 at `sm->offset`, jump to the tail.

The error-path jump bypasses surrounding short-circuit and Not ops so the eval-error flag survives surrounding boolean operators all the way to event.c's header surfacing — but only when the AST replay actually reaches the errored leaf. A guard like `(x != nil && x.I32 == 1)` correctly short-circuits the AND when `x` is nil; the errored leaf (`x.I32 == 1`) is never read by the replay, so no eval_error surfaces. This preserves the user's written short-circuit semantics. The "unguarded error → fail-open" behaviour is preserved for leaves that *are* actually reached by the surrounding short-circuit logic.

Polarity tracking through `Not` ops in the entry-side gate matters for soundness: pure-return subtrees must prune to a constant that flips back to "true" (the safe value at the gate output) after any wrapping NotOps. Without polarity tracking, `!(@return == X)` under an AND with an entry leaf would falsely suppress the return event. `emitGate` carries a `negated` flag through NotOps and emits 0 or 1 to keep the gate output safe.

**Best-effort entry short-circuit**: when the entry-only slice of the AST is provably false (the gate evaluates false), the entry-side condition's tail `SM_OP_CONDITION_CHECK_PRESERVE_ERROR` sets `condition_failed=true`. event.c skips the entry event AND the deferred `in_progress_calls` insertion; the return event then sees `CALL_DEPTHS_ABSENT` and is suppressed naturally. No insert-then-delete dance.

**Throttler**. Split-condition entry uses `ThrottleNone`, return uses `ThrottleAfterCondCheck` so the user's per-second budget isn't halved.

**Storage**. `probe_id` narrows from uint32 to uint16 to make room for `condition_state` alongside it on `call_depths_entry_t` (still 24 bytes total). The compiler asserts `probeIdx < 1<<16` for entry/return-paired probes; line probes don't insert into `in_progress_calls` and tolerate any probe index. The `IssueKindConditionCarryTooLarge` cap is at 8 entry-side leaves (16 bits / 2 bits per leaf).

**IR / SM ops added**

- `ConditionStateInitOp`: clear `condition_state` at the start of the entry-side driver.
- `ConditionLeafEvalOp{LeafIdx}`: lowers to (`CallOp leafFn`, `ConditionLeafRecordOp`). The driver issues one per entry leaf.
- `ConditionLeafLoadOp{LeafIdx, ErrorTarget}`: reads `condition_state[i]` and dispatches per the rules above. Used in both the entry-side gate and the return-side AST replay.
- `ConditionCheckPreserveErrorOp`: like `ConditionCheckOp` but does NOT clear `condition_eval_error`. Used at the tail of split-event-kind drivers so a per-leaf load's eval-error flag survives.
- `ConditionLeafCompleteOp`: emitted at the tail of a per-leaf SM sub-function on the success path. Clears `condition_eval_error` so the driver's `RECORD` can distinguish completion from abort.
- `ExprPrepareOp` at IR level: existing SM op, exposed at IR so the driver can re-prepare scratch between per-leaf calls and the AST replay.

**Verifier-budget note**. The new design adds N+1 SM functions per split-condition probe (one driver + one per leaf, max 9). All share the same `sm_loop` BPF subprog, so the deepest BPF call chain (`probe_run` → `sm_loop` → `sm_swiss_map_aese`) is unchanged. event.c's `probe_run_with_cookie` frame stays at 136 bytes by writing `call_depths_delete` out-parameters directly into `stack_machine_t` fields rather than into stack locals.

### Motivation

Often you want to look at some properties of arguments and then something about `@duration` (like it was slow) or something about the return (there was an error?). 

### Describe how you validated your changes

Eleven new probes in `simple.yaml` exercise the cases this change enables and the soundness behaviours:

**Basic shapes**:
- `condCompound_split_return_and_param`: `@return == 2 && a == 1`
- `condCompound_split_or`: `a > 4 || @return < 5`
- `condCompound_split_not`: `!(a > 4) && @return == 2`
- `condCompound_split_or_of_ands`: `(a > 4 && @return > 5) || (a < 3 && @return < 5)`
- `condCompound_split_duration_param`: `a > 4 && @duration > 0.0`
- `condCompound_split_entry_false`: `a > 100 && @return == 2` (entry forces false → return event suppressed)
- `condCompound_split_max_carry`: 8 entry leaves under AND with one return leaf
- `condCompound_split_carry_overflow`: 9 entry leaves → rejected with `IssueKindConditionCarryTooLarge`

**Polarity / Not interaction**:
- `condCompound_split_not_around_return`: `a > 4 && !(@return == 2)`
- `condCompound_split_not_around_return_or`: `a > 4 || !(@return == 2)`

**Short-circuit + error semantics**:
- `condCompound_split_guarded_nil_deref`: `(x != nil && x.I32 == 1) && @return == 1` — fires only on match; the nil case correctly short-circuits without surfacing eval_error.
- `condCompound_split_guarded_or`: `(x != nil && x.I32 == 1) || @return == 99` — guarded AND short-circuits silently when x is nil.
- `condCompound_split_unguarded_nil_deref`: `x.I32 == 1 || @return == 99` — preserves "unguarded error → fail open" with `eval_error=2`.
- `condCompound_split_or_short_circuits_error`: `@return == 0 || x.I32 == 99` — when the OR's left is true, the errored right leaf is not surfaced.
- `condCompound_split_entry_nilderef`: `x.I32 == 300 && @duration > 0.0` — nil-deref on the only entry leaf fails open.

The full `TestDyninst/simple` integration suite passes across all toolchains (1.23, 1.24, 1.25, 1.26rc1) and architectures (amd64, arm64). The existing `TestDurationThreshold`, `TestThrottler`, `TestFirstFlushFailDropNotification`, `TestDropNotifications`, `TestEndToEnd`, and the full snapshot-test suite continue to pass.
