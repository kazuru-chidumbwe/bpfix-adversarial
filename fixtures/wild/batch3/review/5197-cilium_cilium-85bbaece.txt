bpf: Fix should_redirect_peer under netkit

Commit 210b5866e0 ("bpf: migrate netkit-specific runtime check to
loadtime check") replaced the per-skb runtime check
ctx_get_ingress_ifindex(ctx) > 0 in should_redirect_peer() with the
loadtime !CONFIG(enable_netkit) check. The author's intent was to fold
the netkit Pod -> Pod case (skip redirect_peer, let netkit's own xmit
handle the ns switch) into a constant the verifier can fold away.

But CONFIG(enable_netkit) is global - it is set true for every BPF
program on a netkit node - all get it from lnc.DatapathIsNetkit). So
the new clause also fires for the node-external -> local Pod path
(bpf_host on the physical netdev), where we DO want redirect_peer on
netkit: it deposits the packet straight into the target Pod netns RX
side. Without redirect_peer there, the RX performance gains are gone.

Fixes: 210b5866e0 ("bpf: migrate netkit-specific runtime check to loadtime check")
