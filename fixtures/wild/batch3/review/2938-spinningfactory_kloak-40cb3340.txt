feat: add trusted DNS server whitelist for chain of trust (#73)

* feat: add trusted DNS server whitelist for chain of trust

Only DNS responses from trusted servers populate dns_ip_map, preventing
DNS spoofing. The whitelist is always active:
- kube-dns ClusterIP is always auto-discovered and trusted
- User can add extra IPs via controller.dns.trustedServers (deduplicated)
- If neither source provides IPs, all DNS is rejected (fail-closed)

BPF: trusted_dns_servers map + dns_whitelist_enabled flag. kprobe reads
peer IP from sock struct, kretprobe validates against whitelist.

* fix: validate DNS whitelist for unconnected UDP sockets

Read peer IP from msg->msg_name in kretprobe for unconnected UDP
sockets (musl libc, c-ares use sendto not connect). Previously
has_peer_ip was always 0 for dport=0, bypassing the whitelist entirely.

Also make the e2e DNS whitelist test use an authoritative CoreDNS
(no forwarding) so no process resolves the hostname via kube-dns,
and add services:get RBAC for kube-dns auto-discovery.
