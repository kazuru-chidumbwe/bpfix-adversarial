dyninst: filter() expression operator over slices and swiss maps (#50909)

### What does this PR do?

Implements `filter(coll, predicate)`, returning the elements of a slice or swiss-map collection that satisfy `predicate`. Result lives in capture-expression and message-template position; nested use is rejected.

Pipeline
- exprlang/irgen: parse `filter` into a typed FilterExpr; irgen synthesizes a per-call-site type pair (handle + element/pair) and lowers the inline marker op plus a deferred enqueue_pc loop. The handle's user-visible name mirrors the source collection (`[]int`, `map[string]int`).
- compiler: 8 new SM opcodes plus type handlers that emit the deferred loop body, including a per-element CallOp so nested pointer chases fire on every emitted element.
- BPF: a new DYNAMIC_SIZE_CLASS_FILTER_DEFERRED size class skips the chase preamble's serialize so each iteration emits its own data item. Filter helpers in filter.h re-derive map pointers via bpf_map_lookup_elem internally (no `global_ctx_t*` argument) and bitmask-clamp sizes/offsets to keep the verifier happy.
- decoder: new filter-type decoders walk all data items of the per-call-site type, sort by output_index, and surface ExprStatusTruncated as `notCapturedReason: "collectionSize"`. ExprStatusBits widens from 2 to 4 to make room for the new status.

### Motivation

Filter is very useful

### Describe how you validated your changes

Tests
- New simple-binary probes for slice/map filter, plus a negative probe for `len(filter(...))` and a condition-position rejection probe.
- Regenerated irgen IR snapshots, compiler snapshots, and integration decoded fixtures for all toolchains.
