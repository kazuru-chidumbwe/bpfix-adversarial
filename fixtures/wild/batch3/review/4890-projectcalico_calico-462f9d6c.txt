felix: strip trace-printk from main BPF programs under lockdown via prog_flags

The preamble fix stops the constant per-attach dmesg spew, but the main
dataplane programs still reference bpf_trace_printk unconditionally
(skb_log, the policy Log action, is gated at runtime rather than by
BPFLogLevel, so it survives into the no_log builds). Loading the main
program set therefore still emits a one-off "could not enable
bpf_trace_printk events" burst on every Felix program-load cycle under
kernel lockdown=confidentiality.

Rather than doubling the compiled program matrix with _notrace variants,
give each program a small struct prog_flags in its own frozen
.rodata.prog_flags section (kept apart from the node-wide globals so it
does not perturb their layout). prog_flags is the vehicle for per-program
load-time feature flags. When Felix detects confidentiality lockdown it
sets no_trace_printk before load (SetNoTracePrintk -> Map.SetProgFlags,
wired through loadObject); the bpf_log macro and skb_log guard on it.
Because the section is read-only and frozen, the verifier folds the flag
to a constant and dead-code-eliminates the guarded branches, so the
loaded program references no trace helper and its load is silent.

Verified with a new bpf/ut load test that loads a main program with the
flag set and clear and asserts the trace-printk call instructions are
present only when clear.
