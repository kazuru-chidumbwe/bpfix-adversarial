[CWS] Remove kernel-side DNS event sampling (#55967)

## What does this PR do?

Removes the kernel-side DNS event sampling mechanism in CWS.

## Motivation

Fix a regression: Enabling security profile v2 by default (#55662) caused DNS security rules (e.g. mining-pool domain rules) to stop matching. Bisecting pointed at that PR even though its diff only flips config defaults.

Root cause: enabling v2 force-enables DNS event sampling (`EventSamplingDNSEnabled`). In the kernel, DNS request events are **always** delivered to user space (unlike `open`/`bind`/`connect` syscall events, which are dropped in-kernel unless a rule approver or the sampler admits them). Despite that, the DNS sampler marked admitted events with `EVENT_FLAGS_SAVED_BY_AD`, and the rule engine skips any event carrying that flag:

```go
// pkg/security/rules/engine.go
if event.IsSavedByActivityDumps() {
    return
}
```

So DNS sampling reduced no kernel→user-space volume and only hid a slice of DNS traffic (up to the sampler's per-period budget) from rule evaluation. In low-volume scenarios essentially every DNS query fell inside the budget, so rules never matched.

## Change

- Drop the `approve_dns_sample` branch in `reset_dns_event` (the traced-PID activity-dump branch, which only sets `ACTIVITY_DUMP_SAMPLE` and never `SAVED_BY_AD`, is kept, so manual/traced dumps still capture DNS).
- Remove the `approve_dns_sample` helper, the `DNS_SAMPLE_LIMITER` rate-limiter slot (and shrink `global_rate_limiters`), and the `event_sampling.dns.*` config surface + eBPF constants.
- Security profile v2 already inserts DNS into profiles from the always-delivered user-space event (`ManagerV2.ProcessEvent` filters on container + configured event types, not on the AD-sample flag), so profile collection is unaffected.
- DNS probe activation for profiles now derives from `SecurityProfileV2EventTypes` via `isNeededForSecurityProfile`, instead of piggybacking on the sampler.

Response-side rcode discarders (short vs full DNS responses) are untouched.

## Describe how you validated your changes

- `dda inv system-probe.build-sysprobe-binary` compiles.
- `bazel build //pkg/security/ebpf/c/prebuilt:runtime-security{,-syscall-wrapper,-fentry}` compiles and links.
- Manual/functional verification that DNS rules match with security profile v2 enabled: deployed to staging and validated that DNS events are back.
