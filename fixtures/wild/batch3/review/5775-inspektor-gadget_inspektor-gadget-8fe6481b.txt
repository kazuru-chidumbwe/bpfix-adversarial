profile_cpu: reduce BPF stack frame size for older kernels

Move struct key_t from a stack-local variable to a per-CPU array map.
This reduces the BPF stack frame by ~148 bytes, avoiding the 256-byte
verifier limit when tail calls are combined with BPF-to-BPF subprogram
calls on kernels < 6.13. See the previous commit for details.

The per-CPU array element is zeroed before use via bpf_map_update_elem
with a static const zero-initialized key, since key_t is used as a hash
map key and must not contain stale data from previous invocations.
