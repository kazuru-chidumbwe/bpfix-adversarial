gadgets/advise_seccomp: Keep syscall index 64-bit

Clang 21.1.8 can compile the unsigned int syscall index into a 32-bit
bounds comparison followed by a 64-bit mask before map pointer arithmetic.
On Azure Linux 3 kernel 6.6.157.1-1.azl3, the verifier retains u32_max=499
but uses umax=511 at the byte store into the 501-byte map value and rejects
the program. The same artifact loads on Ubuntu 6.8.0-138-generic.

Keep the index as __u64, matching the raw tracepoint argument width, so
the bounds comparison constrains the full-width scalar used for indexing.
With Clang 21.1.8-8 this emits a 64-bit comparison and no indexing mask.
Preserve the existing bounds check and all map, WASM, and metadata layouts.
Negative/sign-extended syscall numbers still fail the unsigned upper bound.
This is a compiler/verifier compatibility fix, not a demonstrated runtime
out-of-bounds fix or a change to LLVM itself.

Both existing gadget unit subtests pass with the patched source compiled
by Clang 21.1.8-8 and Clang 18.1.8 on the affected x86_64 AZL3 kernel.
The unmodified Clang 21 artifact fails both there. The patched Clang 21
artifact also passes both subtests on the upstream x86_64 kernel-image
matrix from 5.10 through 7.2; 5.4 skips the test's existing 5.6 minimum.
Both compiler versions cross-compile the fixed source for arm64; arm64
runtime validation remains pending.
