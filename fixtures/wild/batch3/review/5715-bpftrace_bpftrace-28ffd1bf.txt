Align variable scratch buffer slots to 8 bytes (#5377)

Variables that don't fit on the stack live in a per-CPU scratch buffer
where every slot is as wide as the largest such variable. The slot size
was not rounded, so when the largest variable had a size that wasn't a
multiple of 8 (e.g. a 20-byte string) every other slot, and every slot
on CPUs past the first, could start at a misaligned offset.

bpftrace's own loads tolerate this on architectures with efficient
unaligned access, but the address of a variable can now be passed to C
code with `&`. The verifier always requires aligned atomic operations,
so an atomic on a field of a struct variable in the scratch buffer was
rejected with "misaligned value access".

Round the slot size up to 8 bytes so every variable starts 8-byte
aligned. Stack variables don't need an equivalent change: LLVM raises
their alignment when lowering the memset that zero-initializes them.
