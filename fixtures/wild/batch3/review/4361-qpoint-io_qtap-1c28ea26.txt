feat: add MySQL-over-TLS support via STARTTLS (#263)

* feat: add MySQL-over-TLS support via STARTTLS

Add STARTTLS support for MySQL connections:
- Hook SSL_set_fd to pre-populate ssl-to-fd mapping before TLS upgrade
- Detect TLS upgrade on MySQL connections (re-emit IsTLS protocol event)
- Handle TLS upgrade event in Go reader (preserve parser state)
- Add /lib64, /usr/lib64, /opt to library search paths for RHEL/Oracle

MySQL performs a plaintext handshake then upgrades to TLS mid-connection.
Without SSL_set_fd pre-population, the first SSL_read after upgrade has
no fd mapping and data is lost.

* fix: re-emit protocol event on STARTTLS TLS upgrade

When a STARTTLS protocol (MySQL, Postgres) upgrades to TLS mid-connection,
the socket-level TLS detection in init_conn sets is_ssl=true but never
re-emits the protocol event with IsTLS=true. This means userspace never
learns the connection upgraded to TLS, so tlsProbeIntrospected stays false
even though SSL_read/SSL_write data is being captured.

Fix: after detecting TLS on a connection with tls_upgrade_pending, re-emit
the protocol event so userspace gets the IsTLS=true flag. This allows the
reporter to correctly set tlsProbeIntrospected=true when data events exist.

Verified with MySQL 8.4 (TLS 1.3), MySQL 8.0, and MariaDB 11.

* fix: address review - drop /opt, use tls_upgraded field

- Remove /opt from commonLibDirs (too broad)
- Use tls_upgraded=true field instead of duplicate is_tls on STARTTLS upgrade
