bpf: lb: do not drain terminating backends for UDP connections

In Cilium 1.18, PR #40969 retained terminating backends in BPF maps
to allow graceful TCP connection draining.

However, because connectionless UDP datagrams do not contain TCP SYN
flags, subsequent UDP packets from client sockets with existing
Conntrack entries evaluated `!state->syn` as true. This trapped UDP
traffic on terminating pods for the duration of the termination grace
period (20–45s), causing packet loss during rolling updates and pod
deletions.

This change adds `tuple->nexthdr != IPPROTO_UDP` to the connection
draining check in both `lb4_local()` and `lb6_local()`. As a result:
1. TCP connections continue to gracefully drain to terminating backends.
2. UDP packets immediately bypass draining, select an active healthy
   backend, and update the Conntrack entry.
3. Fallback to terminating backends when no active backends exist
   (KEP-1669) remains fully preserved when `svc->count == 0`.

Tests:
- Updated `tc_nodeport_lb_terminating_backend.c` to use TCP, verifying
  that existing TCP connections continue draining to terminating backends.
- Added `tc_nodeport_lb_terminating_backend_udp.c` to verify that UDP
  datagrams immediately redirect to active backends when available, and
  fall back when no active backends remain.

Fixes #48714
