tetragon: Split generic process filters

Splitting generic_uprobe_process_filter into 2 programs, because in
v61 object's it got over 600k verifier instructions and that makes
it hard to add new features.

The tail call graph now looks like following:

  generic_uprobe_event
    └─ TAIL_CALL_FILTER
         ↓
  generic_uprobe_process_filter              [stage 1]
    ├─ selector N rejected
    │    └─ TAIL_CALL_FILTER
    │         └─ generic_uprobe_process_filter [stage 1, selector N+1]
    │
    └─ selector N passes stage 1
         └─ TAIL_CALL_FILTER_2
              ↓
         generic_uprobe_process_filter_2      [stage 2, selector N]
           ├─ selector N rejected
           │    └─ TAIL_CALL_FILTER
           │         └─ generic_uprobe_process_filter [stage 1, selector N+1]
           │
           ├─ selector N accepted, more selectors remain
           │    └─ TAIL_CALL_FILTER
           │         └─ generic_uprobe_process_filter [stage 1, selector N+1]
           │
           └─ all selectors processed
                └─ TAIL_CALL_SETUP

We have a gap between v6.1 and v6.9 kernels where we can't use ITER_NUM=1
setup to enable numberic iterators which shrink the instructions count
(check v6.17 output below).

I assume we still need to live with those kernels for some time,
so it makes sense to split the filter function.
