bpf/tests: Move tests for builtins to BPF unit test framework

unit-test.c was removed by accident (see the Fixes tag), when it wasn't
unused: it used to run in the unit-tests target of test/bpf/Makefile,
and its purpose was to test our implementations of memcpy, memcmp, etc.

We also have an open issue to convert that test to our BPF unit test
framework. The motivation is to compile and run this test on the BPF
target (instead of native), and also to pass it through the verifier.

This commit converts this test to be suitable for BPF and integrates it
as a new unit test. Changes made:

1. Runners were moved to a new C file bpf/tests/builtins.c, where they
will be picked by the unit test framework automatically.

2. Added verifier workarounds in assembly, as simple d8[pos]++ was
compiled by Clang into a bitwise OR operation, when it saw that d8 was
aligned, and pos was 0 or 1. The verifier doesn't support bit operations
on pointers, see the error log:

3. __bpf_memmove_fwd has weird alignment requirements when the size
doesn't divide by 8. For example, when the size is 14, it will read 2
bytes, 4 bytes and 8 bytes, basically requiring the starting address to
be 2 modulo 8. Take into account this quirk and align the buffers in the
tests accordingly.

4. Due to the previous point and the order of stack variables being
non-deterministic, test___builtin_memmove1_single can't call
__bpf_memmove, as it ends up in one of __bpf_memmove_{fwd,bwd}, which
require different alignment. Split the test into two and test both fwd
and bwd versions explicitly on the ranges that don't intersect.

4. Random seed initialization was dropped, as the BPF pseudo-random
generator can't be seeded. random() was replaced by get_prandom_u32().
