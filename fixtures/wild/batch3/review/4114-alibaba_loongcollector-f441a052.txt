perf(ebpf): zero-copy agentsight FFI payloads via arena

Follow-up on the coolbpf bump report (ANOLISA #7112 M4): the C++ side
copied every FFI payload twice - once into std::string record members
inside the callback, then again via SetContent into the event group's
SourceBuffer. Large messages/body JSON (up to MiB) peaked at ~2x.

Records now own a per-record SourceBuffer arena: the callback copies
FFI bytes exactly once, StringView members alias the arena, and
HandleLlmEvent/HandleHttpsEvent hand it to the PipelineEventGroup as
its main buffer (network_observer pattern). Record fields are emitted
with SetContentNoCopy; computed values still copy into the same arena.
Also drop the dead mInputMessageDeltaJson field (never read; the delta
is recomputed locally) and add a CalcSHA256Hex(data, len) overload so
hashing the tools JSON needs no materialized copy.

Output fields, tags and drop semantics are byte-identical. Verified
with agentsight events/message-util/manager unittests (6+26+42) under
Debug+ASAN, including new pointer-equality and record-death contract
tests. Trade-off documented in code: filtered-out sensitive header
bytes now live in the arena until flush instead of batch end.
