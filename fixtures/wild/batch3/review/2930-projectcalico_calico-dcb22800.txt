felix: drop the legacy asymmetric IPIP TC programs

The `ipip` endpoint type exists for IPIP tunnel devices on kernels older
than 5.14 (RHEL 4.18.0-330), where the device is asymmetric: ingress skbs
carry an outer ethernet and IP header while egress skbs are bare L3. That
shape is what `CALI_TC_IPIP` compiles for, and it is the only shape on
which `CALI_F_L3` and `CALI_F_L3_DEV` disagree.

The BPF dataplane does not load on any kernel that old - pre-5.13 kernels
reject every TC object with "number of funcs in func_info doesn't match
number of subprogs", and 5.15 hits the verifier's 1M instruction limit on
`calico_tc_main`. So the eight `{from,to}_ipip_*` objects are dead weight:
they are built, shipped and verified, but never attached.

Felix now maps an IPIP device to the `l3dev` endpoint type unconditionally,
which is what `IPIPDeviceIsL3` already selected on every kernel the
dataplane runs on. The object set drops from 82 to 74, and `CALI_F_L3`
becomes an alias of `CALI_F_L3_DEV` rather than a separate condition.
`dnat_on_plain_dev()` loses its `CALI_F_IPIP` term, which `CALI_F_L3_DEV`
and `IFACE_ENCAPS` already cover for an IPIP device.

Kernel feature detection is untouched: `IPIPDeviceIsL3` is still detected
and still reported.
