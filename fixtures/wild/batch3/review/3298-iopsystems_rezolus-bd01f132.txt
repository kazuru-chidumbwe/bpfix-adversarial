perf(network_traffic): attach BTF-typed, and stop paying a helper call per field (#1235)

`raw_tp` gives the verifier no argument types, so every field access compiles
to a `bpf_probe_read_kernel` CALL. On a probe whose whole body is ~45 ns, one
or two of those dominate it — which is why adding the host-boundary counters
in #1214 cost +28.8 ns/run (+64%): the predicate added reads, and reads here
are calls.

`tp_btf` hands the verifier the types, so the same field access compiles to a
direct load. Both flavors are now built and `kernel_has_btf()` picks one at
init, the other never loading — the same two-program shape `cpu_migrations`
uses for `sched_switch`.

The reads stay relocatable: `vmlinux.h` applies `preserve_access_index` to
every record, so clang emits CO-RE relocations for a direct access just as it
does inside `BPF_CORE_READ`. Without that this would have been a portability
regression wearing a speedup's clothes.

Disassembly, before any measurement:

    tp_btf/netif_receive_skb    probe_read=0  atomic_add=4
    tp_btf/net_dev_start_xmit   probe_read=0  atomic_add=4
    raw_tp/netif_receive_skb    probe_read=3  atomic_add=4
    raw_tp/net_dev_start_xmit   probe_read=2  atomic_add=4

Measured on a bonded host, both builds in one run under identical load with
`kernel.bpf_stats_enabled=1`:

    main (raw_tp)   250,430 runs   18,092,130 ns   72.2 ns/run
    tp_btf          246,429 runs    7,302,934 ns   29.6 ns/run
                                                   -42.6 (-59.0%)

That does not merely undo #1218: the pre-#1214 baseline was 44.8 ns/run, so
this lands ~15 ns BELOW where the sampler sat before the host-boundary
counters existed. `main` measuring 72.2 here against the 73.6 reported in
#1218 is the methodology agreeing with itself.

Counting is factored into one `account()` helper so the two variants differ
only in how they read kernel structs, which is the entire reason to have two.

Correctness was checked separately, because this rewrites every field read.
Running both builds side by side on one host — same tracepoints, same packets,
no ambient subtraction — they agree to within 0.89%, and TX
`network_host_bytes` to 0.00%; the residual is the two agents' read instants
differing on a host moving ~450 MB in the window.

Fixes #1218.
