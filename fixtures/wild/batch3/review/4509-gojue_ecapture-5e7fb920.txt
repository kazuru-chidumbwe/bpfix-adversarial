fix: use actual data_len while reading payload (#882)

This PR fixes a bug in the Go TLS kernel tracing code where the wrong length was being used when reading payload data from user space. The fix ensures that only the actual data length (capped at the maximum buffer size) is read, rather than always reading the full buffer size.

Replaces simple bit masking with proper length capping logic
Uses calculated event->data_len instead of sizeof(event->data) in bpf_probe_read_user() calls
Adopts the BPF-verifier-friendly length calculation pattern used in other SSL/TLS interception modules
