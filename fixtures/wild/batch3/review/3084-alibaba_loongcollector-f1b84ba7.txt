* feat(ebpf): report unparsable AgentSight traffic as raw HTTP

AgentSight只解析三种 LLM API path(Anthropic /v1/messages、OpenAI
/v1/chat|completions|responses、SysOM Copilot),其余一律 warn 后丢弃。
libagentsight 0.9.0 起支持把这类流量降级为 AgentsightHttpsData 上报,但
LoongCollector 侧两处都没接:符号表没有 config_set_enable_raw_https
(开关永远为 false),且 handle_read 的 https 回调传的是 nullptr(Rust 侧
dispatch_event 直接丢弃)。本提交把这条链路接通。

- EBPFAdapter: 新增 config_set_enable_raw_https 函数指针。作为**可选**符号
  加载,刻意不进 `ok` 必需符号检查,否则旧版 libagentsight.so 会被判定
  "符号不完整"导致整个插件不可用;用独立 error string 避免污染必需符号的
  诊断信息。启动日志新增 raw_https_api 表示可用性。
- Config: 新增 ProbeConfig.RawHttpsFallback(bool,默认 false)。
- CommonDataEvent: 新增 KernelEventType::AGENTSIGHT_HTTPS_RECORD。
- AgentsightEvents: 新增 AgentsightHttpsRecord。headers/body 是
  (ptr, len) 长度分隔字段,可能含嵌入 NUL(压缩/二进制 body),因此用
  CopyBuffer 按长度拷贝而非 CopyCStr。
- AgentsightManager: 开关经 config_set_enable_raw_https 注入,并按库是否
  真的接受来同步 mRawHttpsFallback,避免注册一个永远不会触发的回调;
  DrainReadsLocked 据此传回调(关闭时传 nullptr 让 Rust 侧零分配丢弃);
  HandleEvent 拆分为 HandleLlmEvent / HandleHttpsEvent。原始 HTTP 以
  event.name=agentsight.http.raw 输出单条日志,不设任何 gen_ai.* 字段。

默认关闭:原始 body 未做脱敏。AgentsightHttpsData 不携带 session id /
turn id / agent type / container id,关联只能靠 (pid, comm);也没有完整
URL,host 需从 http.request.headers 取。

顺带修正文档 Https 默认值漂移(内置 6 条 -> 7 条,与
AgentsightManager.cpp GetBuiltinHttpsAllowRules 一致)。

未编译验证:本机缺 libbpf-devel 与 Rust 工具链。

* fix(ebpf): stop writing request headers to raw AgentSight HTTP logs

RawHttpsFallback 原样上报、不做任何脱敏,因此输出 http.request.headers 等于把
有效凭据写进磁盘。实测确认:采集日志里出现了 Authorization: Bearer <真实 token>
明文,文件权限还是 root:root 0644,同机器其他用户可读。

改为不输出请求头,只把其中的 host 提取出来,作为 server.address / server.port
上报 —— 与 gen_ai.* 日志已有的字段名一致。之所以不是简单删掉:
AgentsightHttpsData 不携带 request_url,url.path 又是相对路径,丢掉 host 就得到
一条不知道发给谁的 HTTP 记录。请求头仍在内存中保留(供提取 host),只是不落盘。

- AgentsightMessageUtil: 新增 ExtractHostFromHeadersJson()。先查 host,再查
  HTTP/2 的 :authority,最后做大小写不敏感兜底扫描。
- AgentsightManager: 删除 http.request.headers 输出;host 经合成 URL 复用既有
  ParseHostAndPortFromRequestUrl,以便 IPv6 方括号和 :port 拆分只有一处实现。
- AgentsightEvents: 注释说明 mRequestHeaders 捕获但永不输出。

实测(langchain-anthropic → anthropic SDK → httpx → libssl):日志中
authorization / x-api-key / http.request.headers 计数均为 0,raw 与 gen_ai 两条
事件的 server.address 同为 idealab.alibaba-inc.com。

未处理的残留风险:http.request.body 仍是原文,部分厂商在请求体内传凭据;
http.response.headers 保留输出,含 set-cookie 时同样敏感。两者都是原始采集的
固有性质,需要 body 级脱敏才能解决。

- 二进制 body 乱码。AgentSight 转发对端实际字节,不按 content-type 过滤,原样

  判定只看字节本身,不看 content-type —— 后者可能缺失或不准。

server.address / server.port —— 后者上游独立采用了同一方案。

* refactor(ebpf): drop unreachable base64 path for raw HTTP bodies

上一个提交给 raw HTTP body 加了"非 UTF-8 则 base64"的分支。实测证明它**不可达**:
二进制载荷在到达本插件之前就已被上游破坏,C++ 侧看到的永远是合法 UTF-8。

证据:向一个不被任何 LLM parser 识别的 path POST 256 字节 0x00..0xFF,采到的
http.request.body.size 是 512,content 是转义 ASCII 加一长串 U+FFFD。512 = 128 个
ASCII 字节 + 128 个非法字节各膨胀为 3 字节的 U+FFFD。

原因在 AgentSight(Rust)侧:
  analyzer/result.rs      request_body / response_body 是 Option<String>,不是 Vec<u8>
  analyzer/unified.rs     用 String::from_utf8_lossy 生成(约 931 / 979 / 1019 三处)
  parser/http/response.rs 解压后同样 from_utf8_lossy
  ffi.rs                  只是取那个 String 的 UTF-8 字节

所以移除 IsValidUtf8() 与 base64 分支,EmitHttpBody 只输出 .content 与 .size,并在
注释里写明为什么不做二进制处理、以及消费方必须知道的两个后果。

同时更正文档:此前「body 的编码」一节承诺 base64 兜底,与实际行为不符。改为「body 的
保真度」并给出实测对照 —— 文本(含 gzip、chunked)忠实且 .size 与 content-length 一致;
二进制静默失真且 .size 虚高,没有任何字段标记这一点。

根治需在上游把 body 改成 Option<Vec<u8>>。AgentsightHttpsData 的 ABI 已是 (ptr, len)
形式,届时本插件侧无需改动,base64 分支可以恢复。已记录在 debug/TODO(含可直接使用的
issue 文本)。

未编译验证。

* docs(ebpf): clarify that AgentSight Https domains do not limit reporting

The Https list only gates which processes get SSL probes attached. Once a
process is attached -- via CmdlineWhitelist or via a domain rule -- all of its
unparsable HTTPS traffic produces raw events regardless of the domain list.

This is deliberate upstream: alibaba/anolisa#1665 removed HttpReportFilter so
that domain rules never filter reporting. Narrowing the domain list therefore
reduces the number of attached processes, not the blast radius of the ones
already attached. CmdlineBlacklist, or disabling RawHttpsFallback, are what
actually narrow scope.

* feat(ebpf): report process metadata on raw HTTPS events

Raw HTTPS fallback events carried only (pid, comm) for attribution,
while gen_ai.* events on the same pipeline already reported agent
type, cmdline and container id. Downstream could not group one agent
process's raw traffic together with its LLM calls.

AgentsightHttpsRecord now copies cmdline / agent_name / container_id
off the C struct (reusing the CopyCmdline / CopyCStr helpers already
written for the LLM record), and FillAgentsightHttpCommon emits them.

The agent type is emitted as plain `agent.type`, NOT
`gen_ai.agent.type`: this event kind exists precisely because the
payload carried no GenAI semantics, so emitting into that namespace
would misrepresent it. The key also matches the unprefixed pid /
comm / cmdline / container.id this path already uses. The gen_ai.*
path keeps gen_ai.agent.type, so a query spanning both streams has
to coalesce the two names.

* fix(ebpf): address raw HTTP review findings on routing, pairing and headers

Five findings from review of the AgentSight raw HTTP fallback. All are on
the RawHttpsFallback path, which is unreleased (not on main), so the
field-shape changes below cost nothing downstream.

Stale-config routing (also affected the gen_ai path):
HandleHttpsEvent/HandleLlmEvent only checked mPipelineCtx != nullptr, then
used whatever mQueueKey was current. mCommonEventQueue is EBPFServer's
shared 8192-entry queue drained by the handler thread, and no teardown path
purges it, so "config A removed, B registered, A's events dequeue" is
reachable and pushed A's un-redacted body into B's queue. Now compares
rec->GetPipelineConfigName() against mConfigName and drops on mismatch,
counting mLossKernelEventsTotal. Dropping before the session-cache update
also keeps A's sessions out of B's delta state.

Response suppressed on unparsable HTTP/2 status:
logCount keyed off status_code == 0, but only agentsight's RequestOnly path
means "no response" by that (it also clears headers/body).
Http2StreamComplete reports 0 whenever the `:status` pseudo-header fails
HPACK decode, with headers and body fully populated — so an entire h2
response was silently dropped, reintroducing exactly what this fallback
exists to prevent. Now keyed on the response payload being present.

Inverted pairing semantics:
the pair shared one event.id and carried no ordering, so downstream dedup
or idempotent writes could discard one half as a duplicate. Split three
ways as the gen_ai path already does: per-log event.id, shared
http.exchange.id as the pairing key, event.sequence for order (needed
because duration 0 makes both timestamps equal). Unprefixed keys, since raw
events emit nothing in the gen_ai namespace.

Credential-bearing headers:
request headers were dropped wholesale and response headers emitted
verbatim — two opposite decisions under one threat model. Both now
filtered and emitted per header. Response side uses a denylist
(kSensitiveResponseHeaders: set-cookie, www-authenticate, ...) because its
diagnostic value is diffuse; request side an allowlist
(kAllowedRequestHeaders: content-type, content-length, traceparent) because
that is where credentials live. Host and user-agent are salvaged into
server.address/.port and user_agent.original rather than the header
namespace. Header names are lowercased locally rather than trusting the
producer, since the match is what makes the filtering sound.
ExtractHostFromHeadersJson became ExtractRequestHeaderFields, returning
host plus the surviving headers from the DOM parse it already did.

Tests: three new cases (stale-config drop, unparsable h2 status, response
denylist) plus TestHttpsEventPairSharesEventId and
TestHttpsEventNeverEmitsRequestHeaders rewritten — both were pinning
behaviour this change corrects.

NOT COMPILED: clang-format and the license check pass, but this has never
been through a compiler. Four signatures changed and three test cases are
new.

* fix(ebpf): harden raw HTTP header filtering and split its self-monitor metrics

Second round of review findings on the AgentSight raw HTTP fallback.

Denylist was systematically bypassable on HTTP/2:
the response-header denylist matches decoded header names, but h2 names come
from decode_headers_stateless(), which has no HPACK dynamic-table state. A name
given as a dynamic-table index becomes the literal "<unknown:N>" while its value
decodes for real; only fully-indexed fields degrade to "<dynamic:N>" and get
dropped upstream. Of the ten denylisted names only set-cookie,
www-authenticate, proxy-authenticate, authorization and proxy-authorization are
in the static table, so on a long-lived connection the second and later
"x-api-key: <secret>" arrived as "<unknown:62>" and sailed past the filter --
the five that failed are exactly the five added to cover vendor tokens.
Header names are now validated as RFC 7230 tokens and the whole entry is
dropped, value included, when the name is untrustworthy: under a denylist a
name you cannot read means you cannot tell whether the header is sensitive.
This also drops Huffman-decode garbage and pseudo-headers like ":status",
which was being echoed alongside http.response.status_code.

Field-name cardinality:
h2 has no upstream bound on header count (HTTP/1 gets 64 from httparse), and
since headers became one field each, "<unknown:N>" was an unbounded field-name
generator. Capped at 64 per log; non-token and over-cap drops are logged rather
than silent.

Metrics could not attribute raw HTTP vs gen_ai:
both streams shared one counter set, so a jump could not be traced to enabling
RawHttpsFallback rather than real LLM traffic growth, and a drop could not be
traced to the stream that filled the shared queue. Raw HTTP volume is expected
to dominate -- every non-LLM exchange of an attached process produces one. The
manager-owned counters are now split by the existing record_type label
(raw_http / gen_ai), following network_observer's AppDetail. The runner-level
mLossKernelEventsTotal / mPushLogFailedTotal stay unlabelled -- they are
EBPFServer's aggregates, shared with three other managers -- so drops now
increment both the aggregate and a plugin-level labelled counter.

Docs:
.encoding never existed (left over from the base64 path removed in 7c28da3c);
the cross-reference to a renamed section was stale too. The chunked framing
claim contradicted the fidelity table: dechunking happens only on HTTP/1
responses, since ParsedRequest has no dechunk or decompress accessor at all, so
HTTP/1 request bodies always keep their framing. Documented as a four-way table
with the two cases where framing survives. Also synced
selfmonitor-cross-reference.md, whose maintenance note makes it a contract.

NOT COMPILED: clang-format, line length, license headers and extern
declaration/definition pairing all check out, but none of this has been through
a compiler. Kept as one commit because the four findings interleave within the
same functions and files.

* fix(ebpf): register the loss counter key so raw/gen_ai attribution works

The per-stream loss counters added in 5c6b11a1 were dead code. AgentsightManager
fetches METRIC_PLUGIN_EBPF_LOSS_KERNEL_EVENTS_TOTAL from the ref built by this
input's kMetricKeys, but that map listed only in/out/out_groups.
ReentrantMetricsRecord::Init creates counters solely for keys in the map,
GetCounter returns nullptr for the rest, and ADD_COUNTER null-checks — so all
four increments (OnLlmCallback, OnHttpsCallback, HandleHttpsEvent,
HandleLlmEvent) were silent no-ops. No build error, no runtime error, the metric
just stayed at zero, which is precisely the attribution the F7 review comment
asked for: which stream filled the shared mCommonEventQueue.

Registers the key, matching InputNetworkObserver's table, and comments the
failure mode above kMetricKeys so the next metric added to the manager gets
registered here too.

The new test lives in InputAgentSightUnittest, not AgentsightManagerUnittest, on
purpose: it asserts through this input's own kMetricKeys, so a missing key fails
it. A copy of the key list in the manager's tests would have kept passing while
production stayed broken — which is why the earlier metrics change shipped with
no test at all.

NOT COMPILED: clang-format, license headers, line length and the
declaration/definition/UNIT_TEST_CASE triple all check out; a compiler has not
run.
