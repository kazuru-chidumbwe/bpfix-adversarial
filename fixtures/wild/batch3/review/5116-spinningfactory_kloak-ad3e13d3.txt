perf(ebpf): shrink the TLS data-plane programs without behaviour changes (#332)

Four changes, each measured with the verifier on arm64 and x86 (release
and KLOAK_DEBUG):

- aes_recover_h: inline aes_block_encrypt once for both AES-128 and
  AES-256 instead of once per key size. The last round key is selected
  from two constants so a runtime round count stays verifier-safe.
  bssl_recover_h (called from the tcp_sendmsg kprobe) loses ~480
  instructions and ~100 bytes of stack.
- tls_conn_state: drop h_powers[16][16], h_powers_ready and wrl_ptr,
  which nothing reads (tc derives the H powers itself, userspace never
  touches the map), and the unused ghash_work.staged_conn. The value
  shrinks from 288 to 20 bytes; bpf_h_extract's stack goes from 376 to
  112 bytes.
- bpf_uprobe_ssl_write: pass the BIO fd read for the server-mode check
  into resolve_host instead of walking SSL -> wbio a second time.
- bssl_recover_h: build the AEADToAESKey offset-scan diagnostic
  (bssl_probe) only in KLOAK_DEBUG builds, as used by the e2e and
  nightly images.

Co-authored-by: Claude Opus 5.5 <noreply@anthropic.com>
