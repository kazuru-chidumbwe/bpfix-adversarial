bpf,loader: explicitly manage policy programs for bpf_lxc and bpf_host

Remove the hack from loadDatapath that pulled out policy maps and programs
before loading a Collection. Explicitly commit them to the global policy maps
as part of loading the endpoint after getting all internal state in order first.

Also removes the POLICY_CALL_MAP macro to ensure stable map name in
CollectionSpec. POLICY_CALL_MAP would evaluate to test_cilium_policy_calls in tests,
while the agent would build the datapath with the macro set to cilium_policy_calls.
This is not compatible with the new way of loading ELFs, so the macro was removed.

The reason for the test_ map prefixes is not documented. With verifier
tests now unflagging maps for pinning, and the loader test suite taking
ownership of /sys/fs/bpf/{cilium,tc}, it doesn't look like there's a strong
reason for keeping the prefixes around. Removing all map name macros is a lot
of churn, so this will follow as its own change set at a later time.

Signed-off-by: Timo Beckers <timo@isovalent.com>
