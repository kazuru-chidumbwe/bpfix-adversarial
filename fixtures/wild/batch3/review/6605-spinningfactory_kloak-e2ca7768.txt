* feat: add HTTP/2 HPACK Huffman support for secret rewriting

The eBPF scanner now detects both HTTP/1.1 plaintext "kloak:" prefix and
HTTP/2 HPACK Huffman-encoded "kloak:" (0xeb 0x41 0xc7 0xd6 0xe7). For
each secret, sync.go stores both a plaintext and Huffman-encoded variant
in the BPF secret_map. The scanner checks for both prefixes and rewrites
with the matching encoding.

- Added is_kloak_prefix_huffman() in helpers.h (5-byte static Huffman)
- scan_chunk checks both plaintext and Huffman prefixes
- sync.go computes Huffman variants using golang.org/x/net/http2/hpack
- Padded shorter Huffman encoding with HPACK EOS bits (0xFF)
- Go demo switched to default HTTP/2 (removed http1.1 force)

* fix: ensure shadow Huffman length >= real secret for HTTP/2 rewriting

The secret reconciler now generates shadow values whose HPACK Huffman
encoding is at least as long as the real secret's. This is required
because the HPACK length prefix in the wire buffer is immutable — the
rewritten data must fit exactly.

Shadow values are padded with uppercase letters (Z, X) which have
longer Huffman codes (8 bits vs 5-6 for hex digits), inflating the
Huffman output to match or exceed the real secret's Huffman length.

Also fixed the Huffman prefix check to use 4 stable bytes (0xeb 0x41
0xc7 0xd6) instead of 5 — the 5th byte varies depending on the
character following "kloak:" due to Huffman bit packing.

* fix: use PID-scoped uprobes for Go and remove cgroup filter from Go handler

Go binaries are statically linked — system-wide uprobes via overlay
don't work for them. Use PID-scoped attachment (which uses cpu=-1,
all CPUs) for Go's crypto/tls.(*Conn).Write and main exe symbols.

Removed the cgroup filter from bpf_uprobe_go_tls_write since PID-scoped
uprobes only fire for the target process — no cgroup filtering needed.
The exec tracepoint detects the Go binary exec and attaches the uprobe
before Go makes its first TLS call.
