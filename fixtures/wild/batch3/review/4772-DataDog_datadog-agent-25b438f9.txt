[CWS] handle subrepears on exit (#46318)

### What does this PR do?

Handle Linux subreaper reparenting in the process resolver's cache. When a process exits, the kernel may reparent its children to the nearest subreaper ancestor (or init) . Before this PR, the process cache kept stale parent references until the next cache flush (up to 2 minutes), causing events on reparented children to report incorrect parent lineage.

**Key changes:**

- **`childrenCache`**: new reverse index (`PPid → []child PIDs`) maintained alongside `entryCache`, enabling efficient lookup of a process's children on exit.
- **`tryReparentChildrenFromProcfs`**: on exit events (`ApplyExitEntry`, `DequeueExited`), iterates over the exiting process's children, reads their current ppid from `/proc`, and reparents them in the cache. If the new parent is not yet in the cache, it is resolved from procfs.
- **`TryReparentFromProcfs`**: called lazily from `setProcessContext` on every event. If a process on the lineage have exited, it tries to reparent its childs to their new parents.
- **Removed `validLineageResult` cache**: the lineage validation cache (`validLineageResult` field and associated `InvalidateLineageCache`/`invalidateDescendantsLineageCache` logic) is removed. `HasValidLineage()` now walks the ancestor chain directly without caching, which is simpler and avoids stale cache invalidation issues after reparenting.

### Motivation

The CWS agent's process cache did not handle subreaper reparenting, causing `process.parent.*` fields to report the wrong parent for reparented processes.

### Describe how you validated your changes

- **Unit tests**: all existing process resolver tests pass. Added `TestSubreaperReparenting` which builds a tree with a fake intermediate parent, calls `tryReparentChildrenFromProcfs` using real PIDs, and verifies the child is reparented to the grandparent.
- **Functional test**: added `TestProcessSubreaperReparenting` which uses the `syscall_tester` to set `PR_SET_CHILD_SUBREAPER`, build a chain of 50 fork/exit cycles (each intermediate process reparented to the subreaper), and verify that the last process in the chain reports the subreaper as its parent.

### Additional Notes

- When procfs hasn't been updated yet (race with `forget_original_parent`), children stay linked to their dead parent via the Go `Ancestor` pointer. The dead parent object is kept alive by the GC and remains valid for field resolution. The reparenting is retried on the next event.
