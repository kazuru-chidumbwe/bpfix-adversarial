* feat: TLS SNI-based host filtering for non-HTTP protocol support

Replace HTTP-only Host header parsing with protocol-agnostic TLS SNI
hostname resolution. This enables host-based secret filtering for
PostgreSQL, Redis, MySQL, gRPC, and any TLS-encrypted protocol.

eBPF changes (tls_uprobe.c):
- New conn_hosts LRU map: caches {tgid, ssl_ptr} → hostname
- New bpf_uprobe_ssl_set_host: hooks SSL_set_tlsext_host_name(),
  reads the SNI hostname and stores it in conn_hosts
- Replaced parse_host() with resolve_host(): first checks SNI cache,
  falls back to HTTP Host header parsing for Go connections
- SSL_write uprobe now extracts ssl pointer (first param) and passes
  it to resolve_host for SNI lookup

Go changes (uprobe.go):
- AttachTLS now also hooks SSL_set_tlsext_host_name symbol on main
  exe and shared libraries alongside SSL_write

How it works:
1. App calls SSL_set_tlsext_host_name("api.stripe.com") → SNI uprobe
   caches hostname keyed by {tgid, ssl_ptr}
2. App calls SSL_write(ssl, data, len) → write uprobe looks up cached
   hostname using the same ssl pointer
3. Phase 2 compares cached hostname against secret's allowed_host
4. If no SNI entry (Go, or SNI not set), falls back to HTTP Host header

* fix: hook SSL_ctrl for OpenSSL SNI capture

SSL_set_tlsext_host_name is a preprocessor macro in OpenSSL that expands
to SSL_ctrl(ssl, SSL_CTRL_SET_TLSEXT_HOSTNAME, 0, name). Add a new
uprobe on SSL_ctrl that filters for cmd=55 to capture the SNI hostname
on OpenSSL-based apps (Python, Node.js, etc.). BoringSSL exports
SSL_set_tlsext_host_name as a real function and is handled by the
existing uprobe.

Co-Authored-By: Claude Opus 4.6 (1M context) <noreply@anthropic.com>

* fix: zero conn_key padding to prevent intermittent SNI lookup misses

struct conn_key has implicit padding between __u32 tgid and __u64
ssl_ptr. BPF stack is not zeroed between invocations, so the padding
bytes could differ between the ssl_ctrl uprobe (which writes to
conn_hosts) and resolve_host in ssl_write (which reads). This caused
intermittent map lookup failures where the SNI hostname wasn't found.

Fix by reordering fields to minimize padding and using __builtin_memset
to explicitly zero the key before use at all three sites.
