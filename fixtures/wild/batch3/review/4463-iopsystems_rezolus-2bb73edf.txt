* feat(cpu): task_attribution option: export task_cpu_usage only when asked, off by default

cpu_usage keeps its per-task accounting in every configuration: the per-CPU and per-cgroup deltas are computed from each thread's utime/stime baseline, and exited threads' CPU is folded from task_cpu_usage into the exited counters. What task_attribution now gates is the export: the task_info event per new thread (a ringbuf reserve and four string reads), the task_exit event, the refresh read of the sparse per-pid map, and one series per thread in every recording. Off by default. The sends are behind a const volatile switch written before load, so the verifier removes them; the task map and ringbuf handlers are registered only when it is on.
