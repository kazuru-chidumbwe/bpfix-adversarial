fix: increase BPF map sizes for production scale, fix TLS record_len minimum (#144)

* fix: increase BPF map sizes for production scale, fix TLS record_len minimum

Map size increases for clusters with 100s of pods per node:
- tracked_cgroups: 256 → 4096 (was the critical bottleneck — nodes
  with >256 pods would silently drop new containers)
- secret_map: 1024 → 4096 (supports more secrets across namespaces)
- watched_hosts: 256 → 1024 (supports more unique host restrictions)

Map max_entries only affects kernel memory reservation (hash maps grow
dynamically), not BPF verifier instruction budget.

Also fixes:
- record_len minimum: 24 → 17 (TLS 1.3 minimum is 0 plaintext +
  1 content_type + 16 tag = 17 bytes; the old check rejected valid
  small TLS 1.3 records)
- Stale comment: "keyed by pid_tgid" → "keyed by tgid"

Co-Authored-By: Claude Opus 4.6 (1M context) <noreply@anthropic.com>

* fix: guard ct_len against unsigned underflow for small TLS records

When record_len is 17-23 and nonce_len is 8 (TLS 1.2), the subtraction
record_len - 16 - nonce_len underflows. Add an explicit check before
the computation, as suggested by review.
