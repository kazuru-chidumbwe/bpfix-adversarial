dyninst: handle more than 32KiB of data per event (#49555)

### What does this PR do?

Adds infrastructure to send probe-event payloads larger than the per-CPU
scratch buffer (32 KiB) by splitting them across multiple ringbuf
submissions and reassembling them in user-space. Also adds a
side-channel for the BPF program to notify user-space when data was
dropped, so user-space can render partial events instead of silently
discarding them.

### Commits (in order)

This is best reviewed commit-by-commit; the descriptions are detailed
and each commit is self-contained.

1. **`dyninst: add entry_ktime_ns correlation ID to event header`** —
   adds an 8-byte invocation ID (the entry probe's `start_ns`) to
   `di_event_header_t`. User-space uses it to pair entry/return events
   and to disambiguate rapid sequential calls whose
   `(goid, depth, probeID)` keys would otherwise collide.

2. **`dyninst: add continuation/streaming protocol in BPF`** —
   when a probe invocation overflows the scratch buffer, BPF emits
   multiple ringbuf submissions carrying `continuation_seq` and
   `continuation_flags` in the header; the final fragment has
   `flags = 0`. Continuation state lives on `stack_machine_t` (a per-CPU
   map value), not on `global_ctx`, to stay within the verifier's
   512-byte nested-stack budget for `probe_run_with_cookie -> sm_loop ->
   sm_swiss_map_aese`.

3. **`dyninst/output: introduce FragmentedEvent abstraction`** —
   user-space type that yields an `iter.Seq[Event]`. `SingleEvent`
   adapts a single event for backward compatibility. `EventHeader`
   gains `IsContinuation()` / `HasMoreFragments()` helpers.

4. **`dyninst/decode: iterate fragments when decoding events`** —
   the decoder walks all fragments, merging `(itemType, address)` data
   items and keeping the longest byte length so a continuation that
   extends a pointer chase is observed.

5. **`dyninst: drop notifications, eventbuf package, and continuation
   testprogs`** — bundles the user-space half:
   - `pkg/dyninst/eventbuf` — unified `Buffer` state machine that
     reassembles fragments, pairs entry+return invocations, applies
     drop-notification truncation flags, and tracks a shared byte
     budget with time-based eviction.
   - BPF drop-notification protocol (`drop_notify_ringbuf` side
     channel, `di_drop_notification_t`,
     `DROP_REASON_RETURN_LOST/PARTIAL_*`,
     `drop_notify_lost_at` single-slot map, emission at the three
     failure sites in `event.c`).
   - Loader / dispatcher / actuator wiring (`DropNotifyReader`,
     `runDropNotify` goroutine, `EvictOlderThan` forwarder,
     `evaluateDropNotifyEviction` loop).
   - Module sink rewired to `eventbuf.Buffer`.
   - Continuation sample testprogs (`manyPointers`, `manyStrings`),
     `sample.yaml` probe configs, JSON snapshot redactor.
   - Snapshot regen across toolchains/architectures.

6. **`dyninst: drop_tester program and TestDropNotifications
   integration test`** — synthetic HTTP-server testprog with `/bytes`,
   `/bytes_return`, `/chain` endpoints, plus scenarios S1–S7 covering
   baseline, multi-fragment, partial-entry under ringbuf pressure,
   partial-return, return-lost, linked-list chase, and concurrent
   clients.

7. **`dyninst: jsonprune package for post-serialization snapshot
   pruning`** — small package for keeping snapshots stable when payload
   sizes vary.

### Follow-up commits added during review

The remaining commits address review feedback (a uint16-overflow bug
Grant flagged, plus reasonable bounds on what BPF can actually emit)
and add the regression tests that pin the new behavior.

8. **`dyninst: deterministic test harness for first-flush-fails PARTIAL bug`** —
   adds three `TestingKnobs` (`SinkOverride`, `OnLoaderReady`,
   `OnProgramLoaded`) plus a `controlledSink` that wraps the
   production sink and can block `HandleEvent` on demand. Blocking
   stalls the dispatcher's output-reader goroutine and saturates the
   output ringbuf without affecting the drop-notify reader, so tests
   can deterministically observe drop notifications under simulated
   ringbuf pressure. Includes a placeholder test gated behind
   `t.Skip` so CI is green at this commit.

9. **`dyninst/testprogs: add CaptureChainReturn and CaptureStringChain
   to drop_tester`** — pure testprog addition. `CaptureChainReturn`
   has independently controllable entry-side and return-side chain
   lengths (used by the first-flush-fails test). `CaptureStringChain`
   is a chain whose nodes carry strings — used by the fragment-cap
   test to push past `MAX_CONTINUATION_FRAGMENTS * SCRATCH_BUF_LEN`
   (a plain Node chain can't reach the cap because each Node consumes
   a chased-pointers trie slot and the trie tops out at ~1024
   entries; strings flow through `chased_slices` instead).

10. **`dyninst/ebpf: remove broken early-exit ringbuf-availability check`** —
    deletes the `out_ringbuf_avail_space < SCRATCH_BUF_LEN` check at
    the top of `probe_run`. It computed available ringbuf space using
    `RINGBUF_CAPACITY` (hardcoded 8 MiB) rather than the actual map
    size, so it didn't fire for shrunken ringbufs in tests and gave
    wrong answers for any capacity != 8 MiB. The remaining
    `bpf_ringbuf_output` failure paths (continuation_aborted,
    RETURN_LOST on final-submit failure) cover the cases this guard
    was trying to short-circuit.

11. **`dyninst/ebpf: fix continuation_aborted PARTIAL with last_seq=0xFFFF`** —
    the bug Grant flagged. When the *very first*
    `scratch_buf_flush_and_continue` fails (ringbuf saturated at the
    moment of the first mid-chase flush), the previous code in the
    `continuation_aborted` branch sent `PARTIAL_*` with
    `last_submitted_seq` still `LAST_SUBMITTED_SEQ_NONE` (`0xFFFF`).
    Userspace's `NotePartial` does `entryExpected = lastSeq + 1` with
    uint16, wrapping to 0, which `buffer.go:144` semantics treat as
    "still assembling, total unknown" — the entry sits in eventbuf
    until eviction, defeating the notification. Fix mirrors the
    final-submit branch: gate `PARTIAL_*` on
    `last_submitted_seq != LAST_SUBMITTED_SEQ_NONE`, fall through to
    `RETURN_LOST` for return-side / no-op for entry-side when no
    fragments were submitted. Removes the `t.Skip` from the test
    added in commit 8 and restructures it to use the new
    `capture_chain_return` probe with precise saturation math (64 KiB
    ringbuf, free-space window targeting), per-variant assertions,
    `tracePipeCollector` wiring, and a `t.Cleanup(sink.stopBlocking)`
    so a `t.Fatalf` mid-test doesn't deadlock the dispatcher's
    `flushAndWait`.

12. **`dyninst/ebpf: cap continuation fragments at 16 per probe invocation`** —
    adds `MAX_CONTINUATION_FRAGMENTS = 16` in `scratch.h` and rejects
    flushes past the cap from `scratch_buf_flush_and_continue`. The
    caller's existing failure path (`continuation_aborted = true`)
    handles this identically to a ringbuf-full failure: `probe_run`
    emits a `PARTIAL_*` notification and userspace finalizes the 16
    fragments already in flight as a truncated event. Sizing
    rationale: 16 × 32 KiB = 512 KiB raw payload ceiling per
    invocation; with ~2× JSON-serialization blowup, that maps to
    roughly the backend's 1 MiB serialized-snapshot ceiling. Includes
    `TestFragmentCap` as a regression test using the new
    `capture_string_chain` probe with 128 nodes × 4 KiB strings
    (~530 KiB raw, well over the cap).

13. **`dyninst: clamp captured-item size to the largest BPF size class`** —
    `scratch_buf_serialize_whole`'s size-class dispatch tops out at
    8192 bytes. Items configured larger fail the dispatch entirely
    and are silently skipped via the "item too large for single
    buffer, skipping" path in `stack_machine.h`, so e.g. a configured
    `maxLength: 65536` doesn't capture more than 8192 — anything
    between 8192 and 65536 bytes gets dropped instead of truncated.
    Adds `MAX_DATA_ITEM_SIZE` (8192, kept in sync with `SIZE_LIST`)
    and clamps `serialize_len` to it before the dispatch. Strings
    and slices that exceed the ceiling now produce a truncated
    capture rather than a silent skip. The change is observable in
    the `testManyStrings` snapshot regen: a 40960-byte string
    element previously omitted with `notCapturedReason=depth` now
    captures 8192 bytes with `truncated=true`.

### Motivation

Some probes (long strings, deep pointer chases, large slices/maps) want
to emit substantially more than 32 KiB per invocation. Before this PR
the BPF program would silently drop the tail; with continuation +
drop notifications, user-space gets either a complete payload or a
clearly-marked truncated one, never a silently truncated one.

### Describe how you validated your changes

- Snapshot tests across toolchains and architectures
  (go1.23.11 / 1.24.3 / 1.25.0 / 1.26rc1 × amd64 / arm64), regenerated
  for every changed binary layout.
- Property tests and YAML snapshot tests for `eventbuf.Buffer`
  (fragment reassembly, entry/return pairing, drop-notification
  truncation, byte-budget eviction).
- `TestDropNotifications` integration test (scenarios S1–S7) against
  the new `drop_tester` testprog, asserting structural invariants on
  the snapshots collected via fakeintake.
- `TestFirstFlushFailDropNotification` (variants A and B) —
  deterministic regression test for the `last_seq=0xFFFF` PARTIAL
  bug. Verified on the KMT VM that the test passes with the fix and
  fails (catching `last_seq=65535`) when the fix is reverted.
- `TestFragmentCap` — pins the 16-fragment cap. Verified that with
  the cap raised to 256 the test fails (no PARTIAL_ENTRY observed),
  confirming the test really pins the cap and not just any
  truncation behavior.
- Benchmarks for `eventbuf.Buffer`.
