fix(cpu): conserve CPU time of exited tasks (#1037) (#1051)

Per-task CPU attribution was accurate while a task lived and then lost its
entire total at exit. `sched_process_exit` zeroes the exported counter
(mod.bpf.c) at the same moment `handle_task_exit()` clears the task's
metadata, so both the value and its labels are released together and the
series simply ends.

Measured on a 32-core EPYC against the kernel's own accounting for a
pinned single-core burner: the live counter tracks /proc/<pid>/stat to
~0.07% (2948 ticks = 29.48s vs 29.500s) for the task's whole life, then
drops to zero in one step at exit. There is no drip-loss during the run,
and there is no bounded task table or slot eviction -- task_cpu_usage is a
full MAX_PID array and sparse_packed_counters is a bare alias for
packed_counters with no cap, so the mechanism suspected in the issue does
not exist.

This matters more for rezolus than for a live exporter: recordings are
analyzed after the fact, so every short-lived task contributes CPU time
that is invisible in the task view while still present in the cgroup and
host totals, with no indication the two disagree.

Rather than change the retention lifecycle (which would keep dead-task
cardinality alive for a scrape interval), fold the task's total into
exited-task aggregates before dropping it, so the books can be reconciled:
sum(live tasks) + exited ~= cgroup total. O(1), no added cardinality.

Deliberately a distinct metric name rather than another `cpu_usage` state:
this time is a subset of user+system, not a disjoint category, so exposing
it as a third state would double-count any sum across states.

Verified the aggregate gains exactly what the per-task series loses:

  last live per-task value   20.108 s
  exited aggregate before     5.995 s
  exited aggregate after     26.195 s   (delta 20.200 s)

The 92 ms difference is CPU consumed between the final sample and the
actual exit. The host baseline also climbs steadily from other short-lived
tasks exiting, including a +4.6 core-second step that was previously
invisible entirely.
