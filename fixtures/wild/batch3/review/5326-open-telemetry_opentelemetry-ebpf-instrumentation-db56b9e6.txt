Fix BPF verification after loop widening (#3759)

* Fix BPF verification after loop widening

Keep the socket capture remainder check on a bounded 64-bit destination
offset so verifier loop widening cannot separate it from the pointer
arithmetic. Unroll the short hex conversion loops to preserve packet
bounds and keep the traceparent scan within the verification budget.

This restores loading of the affected programs on the pinned bpf-next
kernel while preserving capture limits and trace propagation behavior.

* Separate HTTP traceparent scanning and decoding

Move HTTP/1 traceparent adoption into its own tail-call program so the
header scan no longer explores the nested hex decoding loops. Restore
the shared decoder's bounded loop, since unrolling it pushes the HTTP/2
server parser over the verifier budget on arm64.

Exercise the scan-to-parse handoff over real sockets, including headers
in later scan chunks and malformed values that must not be adopted.
