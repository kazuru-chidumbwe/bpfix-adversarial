Use bpf_probe_read_user_str to reduce noisy error on EFAULT (#52361)

### What does this PR do?

Replaces the fixed-length `bpf_probe_read_user` with `bpf_probe_read_user_str` in `fill_lib_path` (shared-libraries eBPF program), and removes the now-irrelevant `fill_path` wrapper and `fill_path_safe` byte-by-byte fallback

### Motivation

`fill_lib_path` read a fixed 220 bytes (`LIB_PATH_MAX_SIZE`) regardless of the actual path length. When a short pathname sat near the end of a mapped page, the read crossed into unmapped memory and `bpf_probe_read_user` (nofault) failed with `EFAULT`. On kernels ≥5.6 the openat fexit probes fire on every open syscall, so this produced a constant ~5% (`220/4096`) stream of `error:efault, helper:bpf_probe_read_user` telemetry, drowning out real errors. No functional impact — the `fill_path_safe` fallback already produced correct paths — purely telemetry noise plus the wasted fallback work. `bpf_probe_read_user_str` stops at the `NUL` terminator, so it never over-reads; the `EFAULT` and the fallback both go away. Available since kernel 4.11, below our 4.14 floor for shared-libraries monitoring.

### Describe how you validated your changes

Built system-probe and ran `./pkg/network/usm/sharedlibraries/... (TestEbpfProgram`, which loads the program and exercises library detection) on a 5.15 arm64 kernel — passes, confirming the program still verifies and detection is unchanged.
