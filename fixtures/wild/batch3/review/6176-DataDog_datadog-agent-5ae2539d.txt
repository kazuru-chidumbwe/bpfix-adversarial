feat(cws): Use task_storage map for dentry_resolver_inputs (#58496)

### What does this PR do?

Back `dentry_resolver_inputs` with a task storage map when `use_syscall_task_storage` is enabled, the same way as the `syscalls` map. The LRU map is kept as the fallback on kernels without task storage support.

### Motivation

`dentry_resolver_inputs` carries the dentry resolver input from the cgroup write hook to the dentry resolver tail calls of the same thread, and is never read from user space. Its entries are never deleted, and the map only has 256 entries, so an input can be evicted in the middle of a resolution when many threads write to cgroups at the same time. With task storage, inputs are freed along with the thread and can't be evicted.

### Describe how you validated your changes

Built all the prebuilt eBPF variants (with and without task storage). The verifier and the cgroup write resolution are covered by the functional tests run in CI.
