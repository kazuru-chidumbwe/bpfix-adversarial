fix(scheduler): exclude idle task from involuntary switches (#1046) (#1057)

The idle task is always TASK_RUNNING, so every time a CPU left idle to
run a real task, the idle task counted as having been involuntarily
preempted -- and the count was charged to the root cgroup. Nothing was
competing for the CPU and no task was preempted; the CPU just woke up.

Move the IVCSW and cgroup_ivcsw increments inside the existing prev_pid
guard, the same way #1045 excludes the idle task from the timing paths.

Verified on a 32-core EPYC (kernel 6.12) by reconciling against
/proc/stat ctxt with an independent bpftrace count of sched_switch
where prev_pid == 0. Those switches are now counted in neither class,
so the identity from #1040 must break by exactly that count:

  ctxt - (voluntary + involuntary) == count(sched_switch, prev_pid == 0)

  load (switches/120s)   gap        idle_prev   agreement
  6,864,263              1,525,654  1,527,543   -0.12%
  32,458,279             1,433,842  1,435,058   -0.08%

On clean main the same harness shows the gap at ~0 and the #1040
identity holding to -0.02%, confirming the change removes exactly the
idle->task switches and nothing else.

This changes the values of a shipped metric on every host. The
inflation removed is load-dependent: 65% of reported involuntary
switches on an otherwise idle host, ~30% under load.

Also updates the involuntary descriptions to state the exclusion. The
host-scope description is not currently observable via
/metrics/descriptions, which collapses same-name metrics -- see #1056.
