feat(bpf): implement connection limit enforcement (QoS max connections) (#12602)

* feat(bpf): implement connection limit enforcement (QoS max connections)

Implement per-workload TCP connection limiting for the BPF dataplane
(CORE-11846). The BPF dataplane's bpf_redirect_peer optimization
bypasses the to_wep TC hook for forwarded packets, so connection count
is tied to CT entry lifecycle rather than packet observation.

The BPF program atomically checks and increments a counter in the
cali_qos map on new TCP SYN at both to_wep (ingress) and from_wep
(egress). A Go-side ConnLimitScanner recounts established connections
each CT scan cycle (~10s) and overwrites the counter, serving as the
sole decrement mechanism. Connections that close or time out are simply
not counted on the next scan.

Extend the cali_qos map value with max_connections and current_count
fields (24→32 bytes, version 1→2), reusing the existing map and
spinlock rather than introducing a separate map. Connection limit config
is merged into the per-direction QoS map handling in bpf_ep_mgr
alongside packet rate, with a single read-compute-write per direction.

Rejected SYNs are marked on the CT entry (CALI_CT_FLAG_CONNLIMIT_REJECTED)
so retransmissions are unconditionally rejected even if the scanner has
since decremented the count. Connlimited CT entries also set
CALI_CT_FLAG_SKIP_REDIR_PEER so SYN retransmissions route through
to_wep instead of bypassing via bpf_redirect_peer.

FV tests use getBPFMaxConnections/getBPFCurrentCount helpers to poll the
QoS map for config propagation and scanner convergence, matching the
pattern used by the existing packet rate tests.

closes (both FINs seen or RST), rather than waiting up to 10s for the
Go-side scanner to recount. The decrement runs inside calico_ct_lookup()

* fix(bpf): scanner must skip CT entries with CONNLIMIT_DEC flag

* remove CT_RES_CONNLIMIT_FIRST_SYN, send RST on retransmissions of rejected SYNs

The CT_RES_CONNLIMIT_FIRST_SYN result flag existed only because the CT
lookup eagerly set CONNLIMIT_INGRESS on the entry before tc.c decided
whether to count -- once set, tc.c had no way to distinguish "we just
set it" from "we set it on a previous SYN", so it needed a separate
signal across the lookup -> tc.c boundary.

Defer the CONNLIMIT_INGRESS set to after a successful increment. Now
the flag honestly means "this entry contributed to the counter":
- conntrack.h just propagates INGRESS/REJECTED from the entry to
  result.flags; no eager write.
- tc.c reads result.flags, takes one of three paths:
    INGRESS set    -> retransmission of accepted SYN, allow
    REJECTED set   -> retransmission of rejected SYN, RST
    neither set    -> first SYN: count, then set INGRESS on success
                      or REJECTED on failure
- Both reject arms now jump to PROG_INDEX_TCP_RST. Previously the
  retransmission arm dropped silently (TC_ACT_SHOT, no RST), leaving
  the client to wait out tcp_syn_retries before giving up. It now
  gets an RST promptly, same as the first-SYN reject path.

This also fixes a latent decrement-leak: previously a rejected SYN's
CT entry carried both CONNLIMIT_INGRESS (set eagerly) and
CONNLIMIT_REJECTED, so cleanup-time decrement would deduct a counter
that was never incremented. With the deferred set, rejected entries
carry only REJECTED and the cleanup-time decrement is correct.

A concurrent-SYN race for the same 5-tuple can still leave an entry
with both INGRESS and REJECTED set. The tc.c precedence rule (INGRESS
checked first) treats this as "counted, allow" -- matches what the
winning CPU's increment already recorded. Documented in tc.c.

* split BPF connlimit and packet rate per IP family to match iptables/nftables behaviour

The cali_qos map was keyed by (ifindex, direction) only, so v4 and v6
SYNs on the same veth direction incremented the same counter. That
differs from iptables/nftables, where connlimit rules live in
family-specific chains with independent counters per family. It also
caused dual-stack scanner drift: v4 and v6 scanners both wrote to the
same QoS entry, each overwriting the other's recount.

Add family to the key (now {u32 ifindex, u16 ingress, u16 family}, 8
bytes) and bump cali_qos to v3. BPF helpers pick family from the
IPVER6 compile-time macro; Felix's bpf_ep_mgr writes one QoS entry
per enabled family per (ifindex, direction); each per-family scanner
writes only to its own family's entry, eliminating the drift. With
this change a dual-stack pod gets up to N v4 connections AND up to N
v6 connections — matching iptables/nftables.

* let retransmissions of rejected SYNs re-run the ingress connlimit check

A SYN rejected by the ingress connlimit used to leave a sticky
CONNLIMIT_INGRESS_REJECTED flag on the CT entry, so every TCP SYN
retransmission for the same 5-tuple was unconditionally RST'd —
even if other connections had since closed and the counter was
back under the limit. Now retransmissions re-run
qos_connlimit_check_and_increment; on success the CT entry gets
INGRESS set and REJECTED cleared (mandatory, since
qos_connlimit_decrement_for_ct gates the close-time decrement on
INGRESS && !REJECTED — leaving REJECTED set would leak the slot).

The first-SYN branch and the REJECTED-retransmission branch are
now unified: both run the limit check and react to its outcome.
A `was_rejected` local controls the diagnostic path (log
"limit still full" vs "exceeded") and the REJECTED stamp (skip
when already set).

Reintroduces ct_value_clear_flags in conntrack_types.h (deleted
earlier in this PR as unused) — the second-chance path is its
real consumer.

+ * the current interface and direction using the cali_qos map. If below the
+ * limit, increments the counter and returns 0 (allow). If at or above the
+ * limit, returns -1 (reject). Returns 0 if no limit is configured for this
+ * interface+direction (no map entry or max_connections <= 0).

+static CALI_BPF_INLINE int qos_connlimit_check_and_increment(struct cali_tc_ctx *ctx)
+{

+	 * map is keyed by the host-side primary ifindex. Use host_ifindex
+	 * from globals when available.

+		ctx->globals->data.host_ifindex : ctx->skb->ifindex;

+		.ifindex = __qos_ifindex,

+		.ingress = 1,
+#else // CALI_F_EGRESS
+		.ingress = 0,
+#endif

+#else
+		.family = 4,
+#endif
+	};

+		return 0;
