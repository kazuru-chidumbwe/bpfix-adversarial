test(ci): run the privileged BPF tests and an e2e leg on Cilium, and fix what Cilium exposed (#341)

* test(ci): run the privileged BPF tests as root, and fix those that rotted

CI's Test job built and ran the tests as the runner user, so every BPF test
skipped: the verifier on x86, the DNS rewrite, the tc patch, the connect
redirect, netns and cgroup attaches, bpffs pins were only tested by hand.
The test binaries now run as root (go test -exec "sudo -E"), and a step
fails the job if the BPF objects do not load.

Five tests had rotted unseen: dns_ip_map and conn_ip_map tests used value
structs of an older layout (now the generated types), the sync tests built
maps with sizes from before MAX_HOST_LEN became 64 (now from the
collection spec), and the full-prefix test sliced 42 bytes of a 40-byte
placeholder, a panic that hid the sync tests after it. TestSandboxFromNRI
no longer assumes the host's /var/run link can't be read (it can as root).

* fix(ebpf,controller): work next to Cilium: tc chain, kube-dns endpoints, socket load balancing

Three bugs a Cilium (kube-proxy replacement) cluster exposed:

- kloak's tc programs returned TC_ACT_OK, which ends the program chain
  with TCX and with cls_bpf. On a hook a CNI also uses (Cilium's programs
  on the pod's host-side veth), kloak's TCX program, appended after
  Cilium's, never saw a packet, and in clsact mode kloak's priority-1
  filter kept Cilium's from running. They now return TC_ACT_UNSPEC
  (TCX_NEXT) and attach at the TCX head.
- Under socket load balancing a pod's DNS query goes to a CoreDNS pod
  directly, so the answer comes from its address, not kube-dns's
  ClusterIP, and no answer was trusted. The trusted DNS servers now
  include kube-dns's endpoints, kept current by TrustedDNSReconciler (a
  Role in kube-system to watch the Service and its EndpointSlices), and
  PopulateTrustedDNSServers removes the servers that went away.
- Cilium's connect hook on the root cgroup runs after kloak's on the
  kubepods cgroup and replaces a Service's ClusterIP with a backend's, so
  a secret restricted to the Service's IP was refused, and getpeername
  reported the ClusterIP instead of the fake IP. The connect hooks now
  record the address and port each TCP socket connected to (vip_sock_dst),
  which the virtual-ip socket check uses, as kube-proxy leaves it; and
  getpeername reports the fake IP for any socket whose last connect went
  through one.

* test(ci): run the e2e suite on Cilium (virtual-ip)

A new E2E leg runs the virtual-ip suite on k3s with Cilium 1.20.3 instead
of flannel: kube-proxy replacement (socket load balancing), BPF
masquerading, TCX attach; IPv4 only.

The raw TLS demo's echo server moves out of the client's pod into its own
Deployment behind the same Service: under socket load balancing the
client's connection to it stayed on the pod's loopback, which kloak does
not patch (and under kube-proxy it hairpinned through the veth, putting
the real value in the client's pod).

* test(e2e): run the BoringSSL and Bun demos' echo servers in their own pods

As with the raw TLS demo: on the Cilium leg, the client's connection to an
echo server in its own pod stayed on the pod's loopback, which kloak does
not patch. The BoringSSL, Bun and Bun "Claude Code" demos' echo servers
now run in their own Deployments behind the same Services.

* test(cgroups): cover CreateTransient on a read-only cgroupfs as root

CI now runs the tests as root, where the chmod stand-in for a read-only
cgroupfs skips (root ignores permission bits), and the default-root test
succeeds: CreateTransient's mkdir failures went uncovered. A root-only
test mounts a tmpfs read-only, with and without kloak.slice already there,
