felix: make encapsulation a runtime flag and drop the vxlan object set

CALI_F_TUNNEL was CALI_F_IPIP || CALI_F_WIREGUARD || CALI_F_VXLAN, and
CALI_F_WIREGUARD was #defined as CALI_F_L3_DEV. Felix maps both
IfaceTypeWireguard and IfaceTypeL3 to EpTypeL3Device, so a plain
L3-classified NIC - a MAC-less NIC, a TUN device or a BPFL3IfacePattern
match - compiled as a tunnel and took the tunnel arm at every site.
Encapsulation is a property of the attach point, not of the compiled
program, and the compile flags cannot carry it: wireguard and a plain L3
NIC share the l3 object.

Add a per-attach-point global, IFACE_ENCAPS, set from the set of
encapsulating devices Calico itself owns, and read it at the five sites
that asked CALI_F_TUNNEL. The set is built where the data-interface
regex already collects those names, so a vxlan, ipip or wireguard device
the user owns stays an ordinary host endpoint - deriving it from the
link kind would have silently disabled NAT encap on one.

With encapsulation carried at runtime, the vxlan endpoint type has
nothing left to encode: its object parses packets exactly as the host
object does. Collapse it into EpTypeHost, which drops 8 of the 126
object files and one loaded program layout per direction and family on
every node running an overlay. Default policy moves with it: it seeds
the attach point's own policy jump slot rather than the shared layout,
so it takes the device's encapsulation and vxlan.calico keeps
default-allow while an ordinary host endpoint keeps real policy.

The tunnel-key fast path in calico_tc_main runs before any ctx exists,
so it reads the globals directly through a small helper.

fib_co_re.h's PACKET_HOST repair is now reached by every host endpoint,
so it is narrowed to the case it was written for in f029540a87: a frame
that in-kernel decap delivered with a foreign inner MAC. It no longer
rewrites a broadcast or multicast frame, and it cannot touch an ordinary
NIC's PACKET_OTHERHOST traffic, which the host is meant to drop.

Verified: 118 objects build under -Werror and all pass the kernel
verifier; the largest object across the set grows 29875 -> 30009
instructions (+0.4%) and every from-workload object is unchanged. The
felix-side collapse is pinned in bpf_ep_mgr_test.go and load_test.go,
both mutation-tested; deriving the flag from the link kind fails two of
them. The BPF sites are a substitution with unchanged per-site meaning,
covered by the existing NAT and encap unit tests. skb->pkt_type is not
writable through BPF_PROG_TEST_RUN's ctx_in, so the PACKET_OTHERHOST
guard has no unit test and rests on the vxlan FV matrix.
