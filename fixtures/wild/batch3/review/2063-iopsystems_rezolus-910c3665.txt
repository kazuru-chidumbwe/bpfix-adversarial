feat(network): count north/south traffic once, at the host boundary (#1214)

`network_bytes`/`network_packets` count TX once per `net_device` the skb is
handed to, not once per packet leaving the host: the kernel fires
`net_dev_start_xmit` in `xmit_one()`, so a bond counts at bond0 and again at
the slave. A bonded host reports ~2x its real egress, VLAN-over-bond 3x. RX is
not symmetric — `trace_netif_receive_skb()` sits above the `another_round:`
label that bonding, bridging and VLAN untagging re-enter through — so the
metric is asymmetrically inflated, which is worse than uniformly wrong.

Adds `network_host_bytes`/`network_host_packets`, the same traffic counted
once at the netdev bound to a device driver.

Additive rather than a filter on the existing pair. Principle 9: summing is
cheap and reversible, un-summing is impossible. A predicate baked into the
probe discards packets permanently and every recording made in the meantime is
unfixable if we later decide differently. The sampler used 4 of its 8
`COUNTER_GROUP_WIDTH` slots, so both totals fit with no extra memory.

The predicate is a bus-parent test (`SET_NETDEV_DEV()`, what
`/sys/class/net/<if>/device` reflects), not `priv_flags`. `IFF_BONDING` is set
on the physical slave as well as the master, so skipping on it would zero a
bonded host rather than halve it — a 2x overcount traded for a 0x undercount.
A priv_flags allowlist also misses tunnels, which set no distinguishing bit,
and ages as stacking drivers land. `dev->dev.type->name` is unsuitable too:
wireless sets `wiphy_type`, so a wifi NIC would read as virtual.

Verified against v6.12 that bond, VLAN, bridge, veth, tun/tap, macvlan,
ipvlan, vxlan, dummy and loopback set no bus parent, and that `virtio_net`
does — so a guest counts its own egress instead of reporting zero.

Named "host boundary", not "wire", because in a guest it is the hypervisor:
virtio egress may be hairpinned to another VM without touching a link, and the
guest cannot tell. The metric claims only what this vantage point supports.

Scope limits documented in docs/metrics.md: container east-west (veth ->
bridge -> veth) touches no bus-parented device and is absent here; VM east-west
is not a gap in the same way, since each guest counts its own side; SR-IOV VF
traffic is invisible to the hypervisor entirely, which is a property of SR-IOV
and needs PF-side hardware counters (#1213).

Refs #1184.

+ *
+ * True when the device has a bus parent — a `struct device` on PCI, USB,
+ * platform, virtio, ... — which is set by `SET_NETDEV_DEV()` and is exactly
+ * what `/sys/class/net/<if>/device` reflects. A driver bound to a bus device

+ *

+ * vxlan, dummy and loopback call `SET_NETDEV_DEV()` zero times, so all of them

+ * counts its own egress rather than reporting zero.
+ *
+ * Note what this is NOT: a claim that the frame reached a wire. In a guest the
+ * boundary is the hypervisor, which may hairpin the frame to another VM on the
+ * same box. The guest cannot know, and does not pretend to — this counts what
+ * left THIS host's stack, which is the only thing this vantage point can
+ * honestly report. `network_host_bytes`'s description says so.
